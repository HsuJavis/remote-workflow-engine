## 1. Observability — transparency of internal state

The owner's first motive for v27 is observability (「以觀測性為主」), and this send-back loop has blocked six times on one property: **the page must not tell the operator something untrue.** BF-1 made the TAG truthful; BF-2/4/5/6 made four sites stop rendering a degraded envelope as data. What is still missing is the rule that decides what the SURFACE shows when a route did not answer — and without it the surface has told the operator, in turn, a blank, a `TypeError`, the word `undefined`, and now a number.

### 1.1 The positive rule, as a decision table keyed on verdict × region × subject

Three definitions first, because every prior repair went wrong on one of them:

- **Verdict** — `classifyResponse`'s answer for one route on one tick: `'ok' | 'degraded' | 'fail'` (DES-202). 「Non-`ok`」 means `degraded` or `fail`. How a view obtains it is §2.1's business; the rule keys on the verdict, never on what the body looks like.
- **Region** — the part of a view's container that a given route feeds. `/dag` feeds the figure (svg + cell layer + legend); `/api/runs/:id` feeds the run summary, `#run-usage`, and row-2's APPLIED model; `describe` + `/api/runs` feed the header, chips and history table; `/api/home` feeds the whole home grid; `/api/system` feeds the whole System panel. A route's non-`ok` verdict concerns ITS regions only — regions fed by `ok` routes repaint as usual. (This is what makes the rule compatible with `app.js:383-386` writing the tag and footer on the same tick, and with `workflow.js:369` repainting chips from an `ok` route while `/dag` is degraded.)
- **Subject** — what the region is currently showing: for the workflow page's figure region, the run id whose figure OR marker is on screen; for the run page, the page's one run; for the ported tabs and home, the page itself. A view REMEMBERS its region's subject (a paint-memory field in view state — `workflow.js:338`'s state has `selectedRunId` but nothing that says which run's figure is actually painted, which is precisely why the run-switch case is unstated today).

| # | situation (verdict for route R, region G fed by R) | action on G |
|---|---|---|
| 1 | **poll tick**, R non-`ok`, and G already shows the SAME subject the tick would paint | **write nothing into G.** Last-known stays. The tag (DES-202, `worstOf` over the visible view's routes) is the operator's witness that G is stale; G itself does not change. |
| 2 | **first paint** (G has no paint memory), OR the **subject changed** since G's last paint (a run chip / history row picked a different run — `workflow.js:365`; a panel opened for an agent), and R non-`ok` | **clear G and paint the ONE Unavailable component** — `el('div', 'empty', t(lang, 'unavailable'))`, `system.js:79`'s form with the literal replaced (§3.2) — and record G's subject as 「marker for S」. A previous subject's figure under a newly selected chip is a worse lie than a blank; a blank with no marker is ambiguous with 「still loading」. |
| 3 | R **`ok`** (any prior state of G, marker included) | **repaint G from R's body** and update the memory. An `ok` result always repaints — this is what makes row 2's marker self-clearing and row 1's staleness bounded by the next healthy tick (§4). |
| 4 | one paint function consumes TWO routes' bodies (`paintSwimlane` takes `/dag`'s cells AND `/api/runs/:id`'s `agents[]` for row-2's applied model — `run.js:502`, `workflow.js:327`; `renderLegend` takes both — `run.js:512`, `workflow.js:329`) and only one is non-`ok` | **either skip that paint (row 1), or feed it the LAST-KNOWN body of the non-`ok` route, kept in view state** (`state.lastView`). Never `null`, never `[]`, never `{}`, never a literal — those are constructed inputs and each produces a confident wrong output (the row-2 APPLIED→DECLARED swap, the dropped summary, the fabricated node count). |
| 5 | R `ok` but the body carries a degraded SECTION (`system-info`'s `{reason}` fields — DES-207) | **unchanged: field-level Unavailable component per section**, same string key, inside a normal repaint. This row is DES-207's, cited here only so 「section」 and 「route」 stop being one word: `system.js:74`'s `!res.body` test was written by someone reading a row about sections. |

Then the **three prohibitions** the table implies but the last six rounds show must be written out:

- **P1 — one predicate for 「non-`ok`」.** The verdict is `classifyResponse`'s. A view may read it (`res.status`) or, where only a body is in scope, apply the classifier's own predicate to that body (§2.1). It may not invent a third (`!res.body` at pre-BF-4 `system.js:74`; `dagRes.body || {…}` at pre-BF-6 `workflow.js:319`; `if (!view)` at `run.js:360` as the ONLY guard). A top-level shape check on the array the view renders is permitted as a fail-closed addition.
- **P2 — no view-constructed payload in place of a body.** A view never hands a paint function a value it built to stand in for a route that did not answer. Named prohibited shapes: `workflow.js:326`'s `{ cells: [], edges: [], warnings: [], lanes: [], current: null }`; the `|| []` / `|| {}` fallback arm on a `.body` read (`agent-panel.js:234`, `workflow.js:327`, `run.js:502`); `agent-panel.js:238`'s synthesized record with `tokens:{input:0,output:0}`; and any helper of the `okBody(res, fallback)` kind (IMPL-281's recommendation, `06-impl-log.md:6881`), whose natural call at `:326` is byte-for-byte the defect. **Exempt, explicitly:** a payload PROJECTED from an `ok` body's own fields — `predictedPayload(describe)` for the never-run branch (`workflow.js:62-75`) is a projection of an `ok` `describe`, and DES-206's own v27b clause governs it.
- **P3 — the marker's text is the string table's.** `t(lang, 'unavailable')` — one key, both languages (§3.2). The wire's `degraded` value is rendered ONLY where a REQ already makes reason text a content field — the Issues lists (REQ-067/REQ-139: 「未設定 GitHub 時仍顯示 degraded」, `issues.js:103`, whose server text at `server.ts:463/:480` is a fixed literal) and the agent panel's red `detail` block (REQ-135) — always via `textContent` (D5), and never as the marker itself. `A4-2` (the raw exception message on the wire, `server.ts:616`) is the architect's lane; until it pins the wire vocabulary, the client's rule is 「string-table text as the marker; wire reason only in the two REQ-designated fields」.

**Why the rule is observability and not merely correctness.** Row 1 preserves the last-known render *because* the tag exists: the two together are the operator's two witnesses — 「what you see is from before」 (tag) and 「here is what it was」 (region). Row 2 exists because a blank region under a `degraded` tag cannot be told apart from a slow first load, and a previous run's figure under a new chip cannot be told apart from the new run's figure at all. The server-side half of the seam is already in place — every degrade that reaches a view has a `dashboard_api_degraded` journal line with `route` + closed `reason` (`server.ts:615`, `:1103`) — so an operator who sees the marker can find the cause in seconds; the client's job is to not overwrite the truth in the meantime.

## 2. Replaceability — decoupling & pluggability

### 2.1 Key the rule on the verdict, and say honestly where the verdict is not delivered (D3-5)

BF-8(a) is right about the principle: a view that re-derives 「is this really ok?」 from the body's shape is coupled to the server's degrade envelope — and there are TWO envelopes on the wire today (`{runs:[], degraded}` and `{degraded}`), which is exactly why `!res.body` (pre-BF-4) and `dagRes.body || {…}` (pre-BF-6) were wrong: they were written against a shape, and the shape had a truthy sibling. A verdict-keyed rule is the decoupled one: change the envelope, change `classifyResponse` (one place, unit-tested, `dashboard-lib-connection.test.js`), and no view moves.

But the seam does not deliver the verdict to three of the seven views. `app.js:373-379` computes `results[url]` AND `bodies[url]`, hands `onTick` ONLY `bodies`, and reduces `results` afterwards. `home.js:226`, `run.js:470`, `workflow.js:350/:357` receive a body with no verdict — so they apply `classifyResponse`'s predicate by hand (`!body || body.degraded`) plus a fail-closed shape check (`!Array.isArray(body.running)` etc.). That is `QD3-R1` ≡ `D3-5`, recorded debt, and fixing it is a code change on the DES-206 contract (`onTick(container, bodies, statuses, ctx)` or `{status, body}` pairs) plus a task — out of this dispatch by the reviewer's own bounds.

So the clause must say what the tree can satisfy: **「non-`ok` is the classifier's verdict. Where a `getJSON` result is in scope the view reads `res.status`. Where only a `bodies[url]` entry is in scope — the seam does not yet carry the verdict, D3-5 — the view applies the classifier's own predicate to the body (`absent`, or `'degraded' in body`, `connection.js:48`); a top-level shape check on the array it renders may be ADDED (fail-closed), never substituted. No third predicate.」** That keeps `home.js:231`, `run.js:475`, `workflow.js:357` conforming, points at the seam as the pluggable point, and forbids the two forms that produced every instance of the class. ### 2.2 Why P2 forbids the helper, in replaceability terms

Its natural use at `workflow.js:326` is `okBody(dagRes, {cells:[],…})`, i.e. the defect with a function name. The reviewer concurs (`07-review.md` §5); this file agrees for the replaceability reason: the fallback is where the coupling to a view's own payload shape re-enters.

## 4. Self-sustainability — closed-loop autonomy & lifecycle

A dashboard tab is this round's long-lived process: it must survive an engine self-update, a transient store read failure, hours of polling and its own earlier mistakes without a human reloading it. The rule is judged here by whether the page CONVERGES to a truthful state under fault and RECOVERS to the live state without intervention.

### 4.1 Convergence under sustained fault — rows 1–2 give a stable, truthful fixed point

With row 1, a tab left open through a degraded route reaches a fixed point after one tick: last-known regions + a `degraded`/`offline` tag, and nothing changes until the route answers. No repaint churn (today `workflow.js:326-328` re-erases and re-draws an empty figure EVERY 3 s while `/dag` stays degraded — a busy, wrong loop), no growth (no elements added per tick), no flicker. With row 2, a tab OPENED during the fault reaches a fixed point after one tick too: the marker, and the same tag. Both fixed points are truthful, which is the property `QD3-O3` (D3-3) named as missing: 「alive, busy and wrong」 is the state a self-sustaining design must not have.

### 4.2 Recovery — row 3 is what makes the marker and the stale region self-clearing

Row 3 (「an `ok` result always repaints and updates the memory」) is the half a rule like this usually forgets. Without it, an implementer could satisfy rows 1–2 with a `hasPainted` latch that never repaints after the marker, and the page would stay on 「無法取樣」 until reload. With it, the first healthy tick after the fault repaints from real data, the marker is replaced, the memory says 「figure for S」, and the reducer's un-debounced recovery (`connection.js:27-29`) turns the tag back to `live` in the same tick. Recovery is one tick, no reload, no operator action — the same shape the reducer already has for the tag, now stated for the regions.

### 4.3 What the rule does NOT close, so it is not mistaken for closing it

- **`D3-3` — a throwing view freezes the tag** (`app.js:379` unguarded `await view.onTick`). The positive rule shrinks the throw surface (fewer paths reach a paint function with a bad input) but does not fold a view exception into the tick. Still debt; still the fold shape agreed at v27l (`results['view:<name>'] = 'fail'` + one `console.error`).
- **`D3-4` — the footer stamp.** `app.js:386` runs `updateFooterClock()` every tick. Row 1 makes the skip a designed behaviour, so the stamp over a skipped region is knowingly false. Still debt (zero-task bound); the agreed rule (advance only on a tick that observed ≥ 1 route AND reduced `live`) is one line when a task exists.
- **`QD2-O2` — the ported tabs double-fetch.** `system.js:72`, `models.js:52`, `issues.js:99` ignore `bodies` and re-fetch; harmless in load, but it is the second fetch path REQ-142's visibility gate will not gate. Unchanged by this clause.
- **Memory metabolism at the agent altitude** is out of this round's subject; the 2 KB event-row clip and `?limit=500` + `hasMore` marker (DES-206) are the v27 answer and were verified at Gate 8.
