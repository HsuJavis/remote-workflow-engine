## Summary

The architecture is one data array, one authorization function, one path verdict, one grammar, and a large rename.
The design's job is to make each of those **total** (every input has a named outcome), **typed** (every outcome is a
member of a closed union the compiler and one drift test both see), and **injectable** (clock, storage, probe, realpath,
owner lookup). Eight design-level gaps the architecture left open, in priority order:

1. **Multi-mode tools vs one authz row** (ARCH-087/088). `workspace_push` has four effective outcomes (CAS/`user`;
   asset/`author`+workflow-owner; `scope:'global'`/`admin`; stdio-MCP/`admin`), `workspace_list` and `workspace_delete`
   have two-to-three shapes each. A single `{minRole, ownership}` cannot express that, and pushing the escalation into
   the handler re-creates the v22-H2 "description says admin, `case` checks nothing" drift. **Proposal (DES-138/140):**
   a *mode resolver* on the row — plain code, not a matcher DSL — `authz: AuthzRow | { mode(args): ModeName; rows:
   Record<ModeName, AuthzRow> }`, still evaluated once before dispatch, with a unit test that enumerates every mode with
   a fixture arg set. This is my biggest interface-contract call.
2. **`ErrorCode` as a closed union** (DES-137). `ERROR_CATALOG` keys become the type; `codedError(code: ErrorCode, …)`;
   `ToolSpec.errors: ErrorCode[]`. Two drift locks: every catalog key appears in ≥1 row's `errors[]`; every
   `codedError('X'` literal in `src/` is a catalog key. The envelope keeps its **outer** shapes (rewriting 35 handlers'
   envelopes is not asked for) and unifies the **inner** `error` object: `{code, message, see, detail?}`, `see` attached
   in `toErrEnvelope` from the catalog — never hand-typed in a handler.
3. **`callTool`'s 17 positional parameters** (`server.ts:900-921`) collapse into one `ToolDeps` object (DES-141). ARCH-089
   rewrites every arm anyway; positional threading is the `composeConfig` bug class in a different coat.
4. **`checkMermaid` has boundaries ARCH-097 did not enumerate** (DES-147): an edge naming an *undeclared* node id
   (Mermaid auto-renders it as a plain rectangle — i.e. the black-box shape — so a typo silently becomes a "nested
   workflow"); the same id declared twice; CRLF; `LOOP_LABEL` needs a deterministic cycle definition (SCC-based, `<-->`
   excluded); and honesty about which REQ-112 clauses are *enforcement* versus *guide text* ("wrapped in a subgraph
   whose title names the pattern" and "a skipped path is dashed" are not mechanically decidable — the check is
   `SUBGRAPH_TITLE` non-empty and nothing more, and the ledger must say so).
5. **`pathVerdict` is not pure** if it does symlink containment — `path-containment.ts:13-24` uses `realpathSync` with a
   fallback when the target does not exist yet. Split lexical (pure) from containment (injectable `realpath`) (DES-142).
   Also: ADR-028 says `principal.id ?? 'local'` appears once, but **three** caller-typed namespace sites survive in
   today's tree — `POST /assets/blob/:sha?namespace=` (`server.ts:1992`), `POST /assets/manifest?namespace=`
   (`server.ts:2014`) and `run_start.seedNamespace` (`server.ts:359`). All three must derive from the Principal or the
   "namespace is not a permission" premise is false.
6. **Trigger claims** (DES-149/150): ids are bare `randomUUID()` from two stores (`scheduler.ts:175`,
   `webhook-registry.ts:101`) so the facade probes both; a new version whose `triggers[]` omits a previously-claimed id
   does **not** release it (name-level claim persists until deregister or trigger delete — stated, tested, in the guide);
   the refusal path must advance `nextFire` through the same code `markFailed` (`scheduler.ts:303-317`) uses or
   ADR-031's "1440/day" is actually a refusal per driver tick; a refused `once` is consumed (`enabled=0`) like a failed
   one; `lastError` and `lastRefusalReason` stay distinct fields.
7. **Audit** (DES-151): the action union carries `'agent_log_read'` beside two tool names — make actions a **subset of
   `ToolName`** so the set is drift-lockable; `run_result` returns the user's own payload and is not in the audited set
   — a boundary gap (one more string; simplicity-neutral); `appendAudit` is synchronous under better-sqlite3 so
   "audit before bytes" is trivially ordered — say so and test it with a recording fake, not a timing assertion.
8. **Legacy `params.knobs` rows** (DES-144/146): ARCH-095's "agentType/engine rungs reachable only for `appendPrompt`"
   is false for every pre-v24 version row. Decide: legacy runnable through the old rungs (keeps dead paths alive and
   untestable) or `runnable:false` + typed `LEGACY_REREGISTER`. I argue the latter (owner ruled no compatibility window
   and is the only caller); flagged as synthesizer-decidable, and the dead-rung disagreement with ARCH-095 is named,
   not silently flipped.

## Key points — proposed DES items (04-design.md `signature`/`boundary` conventions; DES-137.., `TASK-` unassigned)

Each item: **signature** (the contract) · **boundary** (every input has a named outcome) · **tests** (file, count floor,
trap closed). Numbering continues from DES-136.

### DES-137 — `ERROR_CATALOG` is the closed `ErrorCode` union; `see` is attached in one place
- **traces:** ARCH-087, ARCH-107, REQ-116, REQ-118
- **signature:** `src/errors.ts`: `export const ERROR_CATALOG = { PARSE_ERROR: {message, see:'workflow_authoring_guide'}, … } as const satisfies Record<string, {message: string; see: 'workflow_authoring_guide' | null}>`; `export type ErrorCode = keyof typeof ERROR_CATALOG`; `codedError(code: ErrorCode, message: string, detail?: Record<string, unknown>): Error & {code; detail?}` — the string parameter is **narrowed**, so a code not in the catalog is a `tsc` error. `ErrEnvelope` (inner object, `mcp-facade.ts`) becomes `{code: ErrorCode; message: string; see: 'workflow_authoring_guide' | null; detail?: Record<string, unknown>}`; `toErrEnvelope(err)` looks up `see` from the catalog — **no handler writes `see` by hand**. Outer envelopes unchanged: run tools keep `{runId, status, error}`, catalog writes keep `{code, error}`, params keep `Err`. `INTERNAL_ERROR` stays the one catch-all key (`see: null`).
- **boundary:** a thrown non-`Error` (should not exist — `errors.ts:6` is the single factory) still maps to `INTERNAL_ERROR`; a `.code` that is a string but not a catalog key (possible only through `catalogResolveErrorEnvelope`'s passthrough, `errors.ts:61-71`) maps to `INTERNAL_ERROR` with the original string in `detail.rawCode` — never smuggled as a typed code. The 15 old tool names produce the **existing** JSON-RPC-level unknown-tool response, not a catalog code (they are not tools; REQ-107 says "unknown-tool error").
- **tests:** `tests/unit/error-catalog.test.ts` (≥6): (a) every `ERROR_CATALOG` key appears in at least one `TOOL_SPECS[].errors` **or** a declared `INGRESS_CODES` list (the 409 webhook codes have no tool row); (b) `grep -o "codedError('[A-Z_]*'" src/**` — every literal is a key (**T4**: a code invented in a handler and never documented); (c) `toErrEnvelope` attaches `see` for a `see`-bearing code and `null` for `INTERNAL_ERROR`; (d) an unknown `.code` string lands in `detail.rawCode`; (e) `tsc` negative fixture (`tests/unit/fixtures/bad-code.ts.txt` compiled with `ts.transpile` + diagnostics) proving `codedError('NOPE', …)` is a type error (**T1**: a refusal path that compiles with a misspelt code is a silent no-op at the client). Oracle is the catalog constant, not the implementation (**T2** avoided: the catalog is *data the implementer does not author freely* — the synthesizer pins its key set in 03-tasks).

### DES-138 — `ToolSpec`: the row shape, multi-mode authz by a resolver, and the `TOOL_SPECS.length === 35` pin
- **traces:** ARCH-087, ARCH-088, REQ-107, REQ-109, REQ-118
- **signature:** `src/tool-specs.ts`: `type AuthzRow = { minRole: Role; ownership: 'none'|'run'|'workflow'|'trigger'|'asset'; adminCrossRead?: true }`; `type ToolSpec = { name: string; entity: Entity; key: 'name'|'runId'|'id'|'number'|null; description: string; inputSchema: JsonSchema /* additionalProperties:false at the root, oneOf for modes */; errors: ReadonlyArray<ErrorCode>; seeAlso?: ReadonlyArray<ToolName>; authz: AuthzRow | { mode(args: Record<string, unknown>): string; rows: Record<string, AuthzRow> }; fixture: { happy: Record<string, unknown>; errors?: Partial<Record<ErrorCode, Record<string, unknown>>> } }`. `mode()` is **plain code on the row** (three tools use it: `workspace_push`, `workspace_list`, `workspace_delete`), returning e.g. `'cas'|'asset'|'global'|'stdio'`; it reads args only, never stores. `TOOL_SPECS` is `as const` so `ToolName` is the literal union. `ENTITY_PREFIX: Record<Entity, string>` (`env` → `models_|system_`, `issue` → `issue_`, …).
- **boundary:** `mode()` must be **total** — for an arg set matching no mode it returns `'invalid'`, whose row is `{minRole:'user', ownership:'none'}` so the handler's schema validation (not authz) produces `INVALID_ARGUMENT` — a wrong-shape call is a schema error, not a permission error (a cold model must be told *which*). A row with `adminCrossRead` must have `ownership:'run'` (type-level: a discriminated variant, not an optional flag on every row). `key: null` is legal only for creators and the two env tools.
- **tests:** `tests/unit/tool-specs.test.ts` (≥12): prefix rule per REQ-107 (`name.startsWith(ENTITY_PREFIX[entity])`, `entity==='run' && key!==null ⇒ key==='runId'`); `TOOL_SPECS.length === 35` (**the literal 35 lives in this test and in `02-architecture.md` only**); no old name present (list of 15, typed in the test as the oracle — **T3**); every description containing `/admin/i` has `minRole:'admin'` or a mode row with it (ARCH-051 pattern); `run_start` row contains both REQ-117 trap sentences (literal strings in the test — **T4**); `mode()` enumerated for every fixture in `fixture.errors` and `fixture.happy` (each resolves to a named mode, never `'invalid'`); `projectToolsList()` is deterministic (two calls, `deepEqual`) and every description ends with `Errors: …` listing exactly `errors[]` in order; every `errors[]` entry is a catalog key (types already guarantee — the test is for the *projection text*).

### DES-139 — `Principal`, `resolveRole`, `authorize()` — total over the union × role × ownership × mode
- **traces:** ARCH-088, ARCH-089, ADR-024, ADR-028, REQ-109
- **signature:** `src/authz.ts` exactly as ARCH-088, with two refinements: (1) `authorize(spec, p, args, lookup)` first resolves `row = 'mode' in spec.authz ? spec.authz.rows[spec.authz.mode(args)] : spec.authz`; (2) the ownership subject id is read from `args[spec.key]` **except** for `ownership:'asset'` (subject = `args.workflow`, or `scope:'global'` ⇒ role-only) and `ownership:'trigger'` (subject = `args.id` probed in both trigger stores via `lookup.triggerOwner(id)` — one method, not `(kind, id)`, because ids are unprefixed UUIDs from two files). `OwnerLookup` is **sync** (better-sqlite3 is sync; an async port here would force `authorize` async for nothing). Return type unchanged from ARCH-088; add `reason: string` on the `ok:false` branch (the sentence the cold model reads).
- **boundary:** `OwnerLookup` is **tri-state on every method**: `runOwner(runId): string | null | undefined` (likewise `workflowOwner`, `triggerOwner`) — `undefined` = the resource does not exist ⇒ `authorize` returns **ok** and the handler returns `RUN_NOT_FOUND`/`WORKFLOW_NOT_FOUND`/`TRIGGER_NOT_FOUND` (authz never leaks existence: a `user` probing ids gets the same not-found as the owner would); `null` = the resource **exists and is ownerless** (an auth-disabled-era run with `runs.principal IS NULL`, a v15 workflow row the backfill missed) ⇒ under auth it is **admin-only**: `user`/`author` ⇒ `NOT_RUN_OWNER`/`NOT_WORKFLOW_OWNER`, `admin` ⇒ ok (this is what makes DES-152's "a `user` never sees ownerless runs" a consequence of authz rather than a second rule). Collapsing `null` and `undefined` would let any `user` read every legacy run's workspace — the matrix has a row for both. `auth-disabled` ⇒ always ok **including** `adminCrossRead` (no `crossPrincipalRead` is emitted because `p.id === null` — no audit row when auth is off; stated so the auditor test doesn't expect one). `loopback-exempt` ⇒ ok only for `{minRole:'user', ownership:'none'}` rows, else `PRINCIPAL_REQUIRED` (carries the `server.ts:876-886` condition into the type). `resolveRole(undefined, id)` with auth enabled ⇒ `'user'` (ADR-028); `principals['*']` present ⇒ its role; an entry whose role string is not in the union is a **config-load refusal at boot** (`main.ts`), never a runtime default.
- **tests:** `tests/unit/authz.test.ts` (≥40, table-driven): the full matrix — 3 principal kinds × 3 roles × {none, run(own/other/missing), workflow(own/other/null-owner), trigger(own/other/missing), asset(own/other/global)} × {adminCrossRead on/off} — generated from arrays so a **row count assertion** (`cases.length === N`) traps a partially written table (**T1**). Map-backed `OwnerLookup`. Separate `tests/integration/authz-owner-lookup.test.ts` (≥6) binds the real stores (`runs.principal`, `workflows.owner`, `schedules.createdBy`, `webhooks.createdBy`) to the port and asserts the *same verdicts* as the unit table for six sampled rows (a lookup wired to the wrong column is the failure this catches).

### DES-140 — `callTool(deps: ToolDeps, name, args, principal)` — one deps object, one authorize, one switch
- **traces:** ARCH-089, ARCH-091, REQ-107
- **signature:** `type ToolDeps = { facade; scheduler; webhooks; webhookBaseUrl; cas; assetSync; mcpProbe; issueReporter; buildModelCatalog; systemInfo; lookup: OwnerLookup; audit: AuditWriter }` (the `continuations`, `mcpRegistry`, `graphAnalyzer` members of `server.ts:900-913` are gone); `callTool(deps, name, args, principal: Principal): Promise<unknown>`; body = `find spec ?? unknownTool(name)` → `validateArgs(spec.inputSchema, args)` (ajv, already a dependency) → `authorize` → `switch (spec.name)` with `default: never` (exhaustiveness over `ToolName`). `Principal` is built once in the `/mcp` handler (`server.ts:1853-1881`) — `authEnabled` and `principal: string|null` are no longer separate parameters anywhere below the edge.
- **boundary:** order matters and is pinned: **schema before authz** (a malformed call by a `user` gets `INVALID_ARGUMENT`, not `FORBIDDEN_ROLE` — the cold model must learn the shape first), **authz before any store read other than the owner lookup**. `ReadContext {authEnabled, principal}` (`mcp-facade.ts:58-61`) is replaced by `Principal` — the v22 masking rule "mask on `authEnabled`, never on `principal == null`" becomes `p.kind !== 'auth-disabled'`, which is the same truth with one fewer flag.
- **tests:** `tests/unit/call-tool-order.test.ts` (≥5): a recording fake for `authorize`/`validateArgs`/facade asserts call **order** and that a schema failure short-circuits before `authorize` (**T1**); `tests/integration/mcp-tools-list-http.test.ts` (rewrite of `mcp-tools-list-schema.test.ts`, **T3**): `tools/list` over real HTTP equals `projectToolsList()` byte-for-byte and contains none of the 15 old names; calling `workflow_run` returns the unknown-tool response.

### DES-141 — `composeConfig()` forwards `principals` and `mcpEgressAllowlist`; `graphAnalyzer` warns once; roles validated at load
- **traces:** ARCH-090, ADR-028, ADR-030
- **signature:** `FileConfig.principals?: Record<string, {role: string}>` → validated to `Record<string, {role: Role}>` by `normalizePrincipals(raw): {ok:true, value} | {ok:false, key, role}`; `FileConfig.mcpEgressAllowlist?: string[]` normalized by the existing `normalizeSeedRefAllowlist` shape (`seedref-egress.ts:60`); both forwarded in `composeConfig()`; an unknown `graphAnalyzer` key ⇒ one `console.warn` naming ADR-025.
- **boundary:** an invalid role string ⇒ boot **refuses** (`process.exit(1)` after the message, matching the existing config-refusal paths in `main.ts`) — a config typo `"role":"admn"` must not silently become `user` for the operator (ADR-028's loud failure is for a *missing* block; a *malformed* block is louder still). `"*"` is a legal key; an email-shaped key is stored verbatim (no normalization — `resolvePrincipal` supplies the id string and equality is exact).
- **tests:** `tests/unit/compose-config-v2-wiring.test.ts` gains **two rows** (`principals`, `mcpEgressAllowlist`) and **loses** the `graphAnalyzer` row (**T3**); `tests/unit/normalize-principals.test.ts` (≥5) incl. the malformed-role refusal; `tests/integration/main-composition-root.test.ts` asserts the boot warn for a stale `graphAnalyzer` block.

### DES-142 — `pathVerdict`: lexical verdict pure, containment injected; the three surviving caller-typed namespaces
- **traces:** ARCH-093, ADR-028, REQ-108, REQ-065
- **signature:** `src/path-verdict.ts`: `lexicalVerdict(dest: Dest, rel: string): Verdict` — pure: normalizes separators (`\` and `/`), rejects `''`, absolute (`/x`, `C:\x`), any `..` segment, NUL byte, `.git` segment anywhere (run-workspace only), reserved prefix on the **first** segment (asset-tree only), and returns `stripped` for `STRIP_RE` matches (`workspace-seed.ts:40`, moved here); `pathVerdict(dest, rel, fs: {realpath(p): string} = nodeRealpath): Verdict` = lexical, then `isPathContained` against `dest.root` **using the injected realpath**. Verdict union exactly as ARCH-093 plus `'NUL'` and `'EMPTY'` reasons.
- **boundary:** a path whose parent does not exist yet cannot be symlink-checked (`path-containment.ts:15-16` falls back to the plain resolve) — the design **states** that a not-yet-created symlink is not detectable and that the write path therefore checks **again after `mkdir -p`** of the parent (verdict before, containment after — two calls, the second with a now-existing parent). `stripped` is a *success-with-note* for seeds and a **refusal** for `workspace_delete`/`workspace_pull` (`INVALID_ARGUMENT`, "that path is never written"). Namespace: `POST /assets/blob/:sha` and `POST /assets/manifest` drop `?namespace=` (a supplied one ⇒ `400 INVALID_BLOB_REQUEST` with a message naming the change), `run_start.seedNamespace` is **removed from the schema** (closed schema ⇒ `INVALID_ARGUMENT`); all three derive `principal.id ?? 'local'` from the same `nsOf(p)` helper `mcp-facade.ts` owns. **This amends the ARCH-091 / interface-table row that lists `run_start`'s `seed*` arguments as "unchanged"** — `seedNamespace` is the one seed key that is a caller-typed partition, and ADR-028's "appears once" cannot hold while it exists; the client plugin's `push_workspace.py` (ARCH-013, separate repo) sends `?namespace=` on both HTTP routes and breaks here exactly as it does on the tool renames S-8 already tracks — one more line in that plugin update, not a new dependency.
- **tests:** `tests/unit/path-verdict.test.ts` (≥30, table): every former `STRIP_RE`/`safeRelPath` (`asset-sync.ts:64`) case lands on the same verdict (the drift lock ARCH-093 asks for — the old cases are copied into the test as **literal rows**, not imported, **T2**); a fake `realpath` returning an escaping target ⇒ `SYMLINK`; Windows separators; NUL. `tests/integration/namespace-derivation.test.ts` (≥4): the three routes/tools, each with a caller-typed namespace, refused; the derived namespace equals the principal id.

### DES-143 — `scanAgentCalls(script)`: the literal-options grammar, line numbers, and what "literal" means
- **traces:** ARCH-096, ADR-029, REQ-110, REQ-111
- **signature:** returns `{labels: string[] /* distinct, source order */; calls: Array<{line; label}>; violations: Violation[]}`; a call is `agent(<expr>, <objectLiteral>)` where the second argument must be a **balanced `{…}` literal** whose keys are identifier-or-string keys and whose values are string/number literals, `true/false`, or (for `schema`) a nested object literal — matched by the string-aware `matchDelimiter` (`workflow-meta.ts:113-126`) and a small key/value scan, **no JS parser**. `label` must be a `'…'`/`"…"` literal (template strings refused). `agent(prompt)` with one argument ⇒ `AGENT_LABEL_REQUIRED`; `agent(prompt, opts)` ⇒ `AGENT_OPTS_NOT_LITERAL`; `model|effort|timeoutMs` keys ⇒ `PARAM_IN_SCRIPT {key}`. Calls inside a nested `workflow()` argument list are **not** scanned (the callee's agents belong to the callee). Every violation carries `line` (1-based, computed from the match index) and `hint` from the catalog.
- **boundary:** `agent` as a property name (`x.agent(…)`, `agentFoo(`) is not a call — the regex keeps `\b` and a negative look-behind for `.`; a commented-out `// agent(` **is** matched by the regex scan today — the design accepts this (a false refusal names the line; the author deletes the comment) and states it in the guide rather than adding a comment-stripper (Karpathy). Duplicate labels ⇒ legal, one spec (ADR-029); `labels` is de-duplicated, `calls` is not. A label that is not a valid identifier (`/^[A-Za-z_][\w-]*$/`, the same regex as the diagram node text) ⇒ `AGENT_LABEL_FORMAT` at scan time so the diagram check never sees it.
- **tests:** `tests/unit/scan-agent-calls.test.ts` (≥25): each violation code with the expected `line`; nested `workflow(` exclusion; duplicate labels; every `GUIDE_EXAMPLES[].script` scans clean (the examples are literal fixtures in the test **and** in the guide; DES-157's test keeps them equal — **T2/T4**).

### DES-144 — `parseParamContract(meta, scriptLabels)` v24 shape; `defaults` and `knobs` refused by name; the legacy-row policy
- **traces:** ARCH-094, ADR-035, adjudication A-2, REQ-110
- **signature:** `ParamContract = { agents: Record<string, AgentParamSpec>; args: Record<string, ParamSpec> }` (`knobs` **deleted** from the type); `parseParamContract(metaParams: unknown, scriptLabels: ReadonlySet<string>, aliasNames): {ok:true; value} | Err` where `Err.code` gains `'AGENT_UNDECLARED' | 'AGENT_DECLARED_NOT_IN_SCRIPT' | 'DEFAULTS_RETIRED'`; `metaParams === undefined` **no longer** yields a canonical contract (`contract.ts:218`) — with ≥1 script label it is `AGENT_UNDECLARED` for the first label; with zero labels (a workflow of pure `workflow()` calls) it yields `{agents:{}, args:{}}`. `workflow_register`'s schema has **no** `defaults` property (closed schema ⇒ `INVALID_ARGUMENT`), **and** `meta.params.knobs` / `meta.defaults` ⇒ `DEFAULTS_RETIRED` naming `meta.params.agents.<label>.<key>.default` (REQ-110's last clause read for both the tool argument and the meta — the same stale example can appear in either place).
- **boundary:** required defaults: `model.default` must be a known alias (`UNKNOWN_ALIAS` at registration — `isKnownAlias`, `contract.ts:94`), `effort.default ∈ Effort` and ≤ `maxEffort`, `timeoutMs.default` integer `1..maxTimeoutMs` — all three refused above the engine ceiling **at registration** (`PARAM_OUT_OF_RANGE`, never clamped; carries over `workflow-catalog.ts:400-418`'s ceiling check to the per-agent shape). `appendPrompt.default` optional, byte-capped, frame-delimiter-checked (`FRAME_CLOSE_FORGERY`, `contract.ts:89`). `skills`/`mcp`: arrays of asset names matching the asset-name rule (`/^[A-Za-z0-9][\w.-]*$/`, no `rwe-` prefix) — existence **not** checked (ARCH-094 note). **Legacy rows** (`params` column holding `{knobs, args}` or `NULL`): the design makes them `runnable:false` with `runnableReason:'LEGACY_REREGISTER'` on `workflow_list`/`describe`, and `run_start` on one ⇒ `LEGACY_REREGISTER` — **no** legacy resolution ladder is kept (see DES-146). This is the synthesizer-decidable call; the alternative (keep `knobs`-era resolution) is priced in §Risks R6.
- **tests:** `tests/unit/params-contract.test.ts` — rewritten (**T3**: today's file asserts a 4-knob canonical contract that no longer exists); ≥30 cases: each new code; each ceiling refused at registration; `DEFAULTS_RETIRED` from **both** sites; zero-label workflow. Oracle values (600000/1024/high) typed as literals in the test, not imported (`DEFAULT_CEILINGS` is what's under test — **T2**).

### DES-145 — `validateUserOverrides(contract, raw, aliasNames, ceilings)` per agent; the closed override schema
- **traces:** ARCH-094, REQ-110

### DES-147 — `checkMermaid`: a line tokenizer + node table + edge table; every refusal enumerated with its line
- **traces:** ARCH-097, ADR-023, ADR-029, adjudication A-1, REQ-111, REQ-112
- **signature:** as ARCH-097, implemented as: (1) **normalize** — `\r\n`→`\n`, `maxBytes`/`maxLines` first (`SIZE`); (2) **line classifier** — each non-blank, non-`%%` line is exactly one of `header | node | edge | subgraph | direction | end`, else `MERMAID_INVALID {line}`; (3) **node table** `Map<id, {shape, text, line}>` — a second declaration of an id ⇒ `MERMAID_RULE_VIOLATION rule:'DUPLICATE_NODE' {line}`; (4) **edge table** — each edge line references two ids; an id **not in the node table anywhere in the file** ⇒ `rule:'UNDECLARED_NODE' {line}` (Mermaid would auto-render it as a plain rectangle, i.e. the black-box shape — a typo must not become a "nested workflow"); `&` anywhere on an edge line ⇒ `COLLAPSED_EDGE`; (5) **agent nodes** — `(["…"])` text matched by `AGENT_LABEL_RE`, else `AGENT_LABEL_FORMAT {line}`; (6) **label diff** both ways (distinct labels; a label drawn twice is legal, mirroring ADR-029); (7) **value triple** — `model` string-equal to `agentDefaults[label].model`, `effort` equal, timeout numeric (`120s`≡`120000`; `\d+(ms|s)` only); (8) **cycles** — build the directed graph from `-->`/`-->|l|`/`-.->`/`-.->|l|` edges (**`<-->` excluded** — a debate is a cycle by definition), compute SCCs; every edge whose endpoints share a non-trivial SCC must carry `|label|`, else `LOOP_LABEL {line}`; (9) `subgraph` with empty/missing title ⇒ `SUBGRAPH_TITLE`; unmatched `end` or unclosed `subgraph` ⇒ `MERMAID_INVALID`. - **boundary — enforcement versus guide text, stated:** REQ-112's "an expansion or a debate is wrapped in a `subgraph` whose title names the pattern" and "a skipped path is a dashed edge" are **not mechanically decidable** (the engine cannot know which fan-out is an expansion); the check enforces `SUBGRAPH_TITLE` non-empty **only**, and the guide carries the rest as authoring rules. The ledger must not claim more. Node **text** may contain `"` only escaped as `#quot;` (Mermaid's own escape) — a raw `"` inside the quotes ⇒ `MERMAID_INVALID`; `<`/`>` legal only inside `<br/>` and `<-->` (a single regex over the whole source after tokenizing, asserted). Empty diagram / header only ⇒ `DIAGRAM_SCRIPT_MISMATCH` with `onlyInScript = all labels` (not `MERMAID_INVALID` — the file is valid, the picture is empty). `scriptLabels` empty and no agent nodes ⇒ ok (pure-`workflow()` composition).

### DES-149 — trigger claims: `claim`/`release` contracts, the facade register sequence, both-store probing, and "omission does not release"
- **traces:** ARCH-091, ARCH-098, ARCH-099, ARCH-100, ADR-026, REQ-115
- **signature:** in each trigger store: `claim(id, workflow): 'claimed' | 'held' | 'NOT_FOUND' | 'ALREADY_CLAIMED'` — two statements inside one better-sqlite3 transaction: `SELECT claimedBy FROM … WHERE id=?` (absent ⇒ `NOT_FOUND`; `=== workflow` ⇒ `'held'`, nothing written; other non-null ⇒ `ALREADY_CLAIMED`), then `UPDATE … SET claimedBy=? WHERE id=? AND claimedBy IS NULL` with `changes===1` ⇒ `'claimed'` (a `changes===0` here is a same-process race that cannot happen under the single-writer assumption and is reported as `ALREADY_CLAIMED`, never thrown). The distinction `'claimed'` vs `'held'` is what the compensation rule below needs — a single conditional `UPDATE` cannot tell null→name from name→name. `release(id, workflow): void` (`UPDATE … SET claimedBy=NULL WHERE id=? AND claimedBy=?` — idempotent by construction), `ownerOf(id): string | null | undefined` (`undefined` = not in this store). Facade `workflow_register` sequence: (1) `catalog.validateRegistration`; (2) for each `triggers[i]`: locate the store (`scheduler.ownerOf(id) !== undefined ? scheduler : webhooks.ownerOf(id) !== undefined ? webhooks : TRIGGER_NOT_FOUND`), ownership (`createdBy === principal.id || role admin`, else `NOT_TRIGGER_OWNER`); (3) `claim` each — on the first non-`'claimed'`, release the ones just claimed **in reverse order**, refuse with `{code, triggerId, claimedBy?}`; (4) `insertVersion`; (5) on throw, release exactly the ids whose `claim` returned `'claimed'` — an id that returned `'held'` (already claimed by the same name by an earlier version) is **not** released on compensation, or a failed re-registration would un-claim a working trigger; the same rule applies to the step-(3) rollback. Duplicate ids in `triggers[]` ⇒ `INVALID_ARGUMENT` before any claim.
- **boundary:** a new version whose `triggers[]` omits an id claimed by an earlier version of the same name **does not release it** — the name-level claim persists until `workflow_deregister` or `schedule_delete`/`webhook_delete` by the creator/admin; the fire path then refuses `NOT_IN_RELEASE` (recorded), which is the observable signal. Stated in the guide as one sentence. A trigger deleted by its creator while claimed ⇒ allowed (their resource), the version row's `triggers[]` keeps a dangling id, `describe.triggers[]` omits it (the store no longer has it) — no dangling-id repair, no refusal. Single-process is assumed (ADR-026): the design adds **no** cross-store lock; the kill-between-steps test below is the evidence the compensation holds.
- **tests:** `tests/integration/trigger-claims.test.ts` (≥20): S-5 in full; both stores probed; the compensation with a store whose `insertVersion` is forced to throw (a subclass override, not a mock of the whole catalog) — asserts `claimedBy IS NULL` afterwards **only** for ids that were unclaimed before (**T1**: a compensation that releases everything looks green on the simple case); omission-does-not-release; duplicate ids. `tests/e2e/register-crash-window.test.ts` (1, Gate 7.5 real): spawn the engine, register with a trigger against a catalog file made read-only between claim and insert (via an env-flag test seam in the facade — `RWE_TEST_CRASH_AFTER_CLAIM=1` throws after step 3), restart, assert the trigger is unclaimed and `schedule_list` shows it.

## Risks

- **R1 (interface, HIGH):** a single `authz` row per tool cannot express `workspace_push`'s four outcomes; if the design
  keeps one row and moves the escalations into the handler, the v22-H2 defect class (advertised "admin", checked nowhere)
  is rebuilt with a fresh coat. DES-138's mode resolver is the minimum that keeps the check on the row and before dispatch.
- **R2 (boundary, HIGH):** an edge naming an undeclared node id is valid Mermaid and renders as a plain rectangle — the
  black-box shape. Without `UNDECLARED_NODE`, a typo in an agent's id passes the grammar, is excluded from the diff, and
  the picture shows a phantom "nested workflow". This is the one place ADR-023's "stricter than a renderer" needs a rule
  the architecture did not list.
- **R3 (boundary, HIGH):** `markRefused` without the `nextFire` advance turns ADR-031's "1440 refusals/day" into one
  refusal per driver tick, forever. A single-tick unit test is green either way; the two-ticks-same-instant test is the
  only guard (DES-150).
- **R4 (testability, HIGH):** 113 test files reference old tool names and 37 reference a retired module or the retired `mcp_provision` tool. If the rename is
  smeared across feature tasks, a mid-tier implementer will "fix" a red test by editing its assertion toward the code
  (T2) or leave a retired one green (T3). One deletion task and one sweep task, with grep targets of zero, are the
  structural answer (DES-159).
- **R5 (interface, MED):** three caller-typed namespace sites survive (`server.ts:359/1992/2014`); ADR-028's "appears
  once" is currently false in the tree. If any survives, "namespace is a partition, not a permission" becomes a
  cross-principal CAS read path.
- **R6 (boundary/consumability, MED — synthesizer call):** legacy version rows. DES-144 makes them `runnable:false` +
  `LEGACY_REREGISTER`. The alternative keeps `knobs`-era resolution, the `agentType` rung and the flat `effectiveParams`
  reader alive — three untestable paths and a second precedence rule the guide must explain. Cost of my choice: the
  owner re-registers every existing workflow once (they are the only caller, and REQ-111 already forces a fresh
  `mermaid` on every re-registration, so the re-registration is owed anyway).
- **R7 (boundary, MED):** the audited action set omits `run_result` (the user's payload). One string. If struck, the
  ledger should say why a cross-principal read of the result is less sensitive than of a workspace file.
- **R8 (testability, MED):** the `AUTHORING.md == builder()` diff test and the `tools/list == projectToolsList()` test
  are oracle-from-code by construction; they are drift locks and must be labelled as such in 05-tests.md next to the
  correctness tests that carry the weight (examples registered; descriptions asserted as literals), or the mid-tier
  reader will count them as coverage of REQ-116.
- **R9 (interface, LOW):** `once` schedules refused at their instant are consumed (`enabled=0`). A creator who claims the
  trigger a minute later expects a fire that will never come; the guide sentence and the `lastRefusalReason` row are the
  only signals. Pause was declined (ADR-031); this is the residual.
- **R10 (boundary, LOW):** the subgraph and dashed-edge clauses of REQ-112 are advice, not enforcement; if the ledger's
  REQ-112 acceptance is read literally ("checked mechanically"), Gate 8 will grade the design short. State it now.

## Conflicts between my three lenses (argued, with the tie-break)

1. **One error envelope everywhere (interface) vs 35 handlers with three existing outer shapes (simplicity).** Contract
   wants `{ok, code, …}` on every tool; rewriting every handler's envelope is unasked-for churn and 113 test files already
   assert the outer shapes. **Tie-break:** unify the *inner* `error` object (`code`, `message`, `see`, `detail`) in one
   function; leave the outer shapes. The cold model reads `error.code` and `error.see` on every refusal — that is the
   contract REQ-116 needs.
2. **Authz as pure data (testability) vs mode-dependent escalation (boundary).** A data-only row is trivially enumerable;
   `workspace_push` needs args-dependent rows. **Tie-break:** a `mode(args)` function on the row — code, but co-located,
   total, and enumerated by a test over the fixtures. Not a matcher DSL (ARCH-088's "no permission DSL" stands).
3. **`pathVerdict` pure (testability) vs symlink containment needs the filesystem (boundary).** **Tie-break:** split; the
   lexical half is pure and table-tested, the containment half takes an injected `realpath` and is tested with a fake;
   the write path calls containment twice (before and after parent creation) because a not-yet-created symlink is
   undetectable — the boundary is stated rather than papered.
4. **Every REQ-112 clause enforced (interface: the guide promises it) vs statically decidable only (testability).**
   **Tie-break:** enforce what a parser can decide (`SUBGRAPH_TITLE`, `COLLAPSED_EDGE`, `LOOP_LABEL` via SCC), state the
   rest as authoring rules in the guide, and say so in the ledger. A rule that cannot be tested cannot be claimed.
5. **Legacy rows keep running (boundary: no user-visible break) vs no dead rungs (testability) vs one precedence rule
   (interface/consumability).** Two lenses against one. **Tie-break:** `LEGACY_REREGISTER`; the break is one typed
   refusal for the one caller, flagged for the synthesizer (R6).
6. **`OwnerLookup` async (interface: matches `RunStore`'s promise-returning methods) vs sync (testability/simplicity:
   `authorize` stays a plain function).** **Tie-break:** sync — better-sqlite3 is sync, `RunStore`'s promises are a
   historical wrapper, and an `async authorize` would make the order-of-calls test (DES-140) a promise-ordering test.
7. **Bigger error detail for the cold model (interface: `known[]` labels, both diff sets, `claimedBy`) vs no information
   leaks (boundary: `NOT_FOUND` must not reveal existence).** **Tie-break:** rich detail on *authoring* refusals (the caller
   owns the inputs), existence-neutral `RUN_NOT_FOUND`/`WORKFLOW_NOT_FOUND` on *ownership* refusals (DES-139).

## Expected disagreements with other lenses

- **Quality-dimensions / consumability** will want `run_start` to *accept* the flat override form with a deprecation
  note "for one iteration". I object: the owner ruled no compatibility window, and a schema that accepts two shapes is
  the exact "two rules to learn" cost adjudication A-2 refused for `defaults`.
- **Simplicity purists** will call the `mode(args)` resolver a DSL. It is a function returning a string, on three rows,
  enumerated by a test; the alternative is escalation logic in the handler, which is the defect class REQ-109 names.
- **Domain/product lens** may want legacy versions to keep running (R6). I hold `LEGACY_REREGISTER`, and flag it rather
  than assume it.
- **Observability lens** may want a per-fire audit of refusals instead of coalescing. ADR-031 settled coalescing; my
  addition is only that the coalesced write must share the advance path with `markFailed` (R3).
- **Security lens** may want `authorize()` to also enforce the `mcpEgressAllowlist`. No — egress is a property of the
  *config content*, not of the principal; it belongs in `AssetSyncService.push` (DES-153) where the URL is parsed, with
  the zero-probe-calls test as the proof.
- **The synthesizer** will ask whether `outputSchema` on `ToolSpec` (DES-158) is scope creep. It is one small object per
  row and the only thing that turns REQ-118's "asserted against its own documented contract" from prose into a check;
  without it the acceptance test asserts `error?.code` and nothing else about a happy response.
- **Someone will propose keeping `parseMetaParams`'s "no meta ⇒ canonical contract" fallback for zero-agent scripts.**
  DES-144 keeps only the zero-label case as `{agents:{}, args:{}}`; a script with labels and no `meta` is refused, because
  REQ-110 says every agent's tunables are declared, and a silent canonical fallback is the T1 shape.
