## Altitude judgment (system vs agent)
From `tech_stack` + REQ-016..021 this is **both**, and the v3 slice splits cleanly by module — apply the fitting altitude per module, don't force the other:
- **Conventional-system altitude:** MCP Provisioning Registry CRUD + typed errors (ARCH-015), Secret store loader (ARCH-016 source half), the D-BIND loopback guard, the D-PROC port-selection/SIGTERM→SIGKILL/temp-dir lifecycle, and the **ARCH-019 boot fail-fast** (an ancestor-walk predicate on a config path) — ordinary store/config/process/boot engineering; the load-bearing content is injectability and boundary-predicate correctness.
- **AI-agent altitude:** the SDK Session-Options Builder (ARCH-017) is the heart of the slice — it decides *what an agent runtime sees* (thinking mode, curated tool allowlist, injected-MCP set, resolved secrets, **and `cwd`/`settingSources`**) for **non-Anthropic models running the full harness**. `SessionInitRecord` is agent-altitude observability (what the model was actually given); `FailureEnvelope` is agent-altitude replaceability/self-sustainability (why an `agent()` resolved `null` instead of fake success). ARCH-018 asset-ingestion policy and **ARCH-019's session-init confinement** both mutate/constrain *agent context assembly* — ARCH-019 specifically closes a leak that happens at **session-init, below every tool-call jail**, so it is agent-altitude confinement riding a system-altitude boot path (exactly D-WORKROOT's "altitude note").
The axis v3 most stresses at the **agent altitude** is self-sustainability + confinement under an *unattended, RCE-capable, no-auth* surface: the SDK harness spawns a CLI subprocess per `agent()` plus N stdio-MCP children per session, the scheduler fires runs autonomously, secrets flow into those children, and **the agent CLI assembles its own context (project CLAUDE.md/memory) from the filesystem layout the engine roots it in** — a channel that bypasses tool arbitration entirely. I apply both altitudes and force neither (no OIDC ceremony pulled forward against D5; no human-UX polish on `mcp_provision`).

## Summary
The v3 seam choices are mostly right and I endorse the load-bearing ones: the ARCH-017 **pure-builder ⟂ impure-spawn split** as the master v3 test seam (everything but the one real Ollama `tool_use` round-trip becomes a pure UT); the **flat config-driven `ProviderProfile`** over a provider SPI (D-PROFILE — incurred debt from the D-F6 thinking-400, not speculative); the **global RunGuard semaphore** promotion (D-DOS); **kill-on-timeout, not abandon** (D-KILL — and the realized code correctly wires `Options.abortController`, not a bare local race, per D-F10(c)); the **typed reason-code taxonomy** with FailureEnvelope-never-fake-success; **hooks-drop-by-construction** (ARCH-018); and for the new module, the ARCH-019 **boot fail-fast + project-free-cwd invariant** as the *right minimal shape* — a pure ancestor-walk predicate + a cwd rule, not a per-run OS jail (consistent with the D-SEC "no uid/namespace jail" ruling). `assertWorkRootIsolated(workRoot, existsImpl)` already takes an injected fs-probe (testable) and `existsSync` already detects `.git`-as-*file* (git-worktree case) as well as `.git`-as-dir — two things I would otherwise have flagged, already correct.

My independent objections concentrate where the design **over-claims purity, under-specifies a boundary, or lets a lifecycle/confinement guarantee straddle a seam or a point in time**. The eight that matter, ranked:
1. **Kill-on-timeout slot accounting is a double-free / never-free hazard** (D-DOS × D-KILL intersection) — the single highest-risk boundary in the slice.
2. **Secret redaction races the transcript tap** — a secret in an MCP child's argv/env can land in `agent-<id>.jsonl` *before* redaction unless redaction is specified at capture time.
3. **ARCH-019's guard is boot-time-only against a runtime-mutable tree** — an agent that writes `CLAUDE.md`/`.git` into its run-workspace subtree re-opens the exact REQ-021 leak at the *next* session-init, which the boot check never re-evaluates. (NEW; the load-bearing new finding.)
4. **`ProviderProfile`'s default for an unprofiled alias must fail *safe*** (thinking disabled), or a future alias re-introduces the D-F6 Ollama 400.
5. **ARCH-019 walks `resolve(workRoot)`, not `realpath` — a symlinked workRoot/ancestor into a project is not canonicalized** and slips past the boot guard, inconsistent with ARCH-016's own realpath-based containment. (NEW.)
6. **The D-BIND guard predicate must be is-loopback, not `=== '127.0.0.1'`** (::1, 127.0.0.0/8) — a string compare is both a false-reject and a bypass.
7. **Secret resolution must be atomic (all-or-nothing)** — a partial-resolve that injects one good handle and passes another through fails-open on the very invariant REQ-018 states.
8. **REQ-021's guarantee is silently coupled to `settingSources` staying `['project']`** (never `'user'/'local'`) — the workRoot guard does *not* cover a global `~/.claude/CLAUDE.md`; only the settingSources exclusion does. That coupling is currently a convention, not a tested invariant. (NEW.)

## Key points

### Interface-contract lens
- **Endorse the ARCH-017 builder signature and its purity as a hard contract.** `(providerClass, alias, config, provisionedRefs, resolvedSecrets) → SDKOptions` is right *only if* `resolvedSecrets` is genuinely passed in and the builder reads **no** env/global/clock. Make purity a stated DES invariant with a UT that runs the builder with a frozen input and asserts determinism. If the builder ever reaches into `process.env` "for convenience," the master seam rots and the slice loses its cheap-UT property. This is the one contract I would gate the whole slice on.
- **Keep `GatewayClient.invoke(prompt,opts)` frozen.** SDKOptions must never leak up through ARCH-004 into orchestration. ARCH-017 lives *inside* the two GatewayClient impls (the realized `claude-agent-sdk-client.ts` builds `Options` locally — correct). This preserves D2 replaceability: swapping the gateway is still a one-interface change.
- **`SecretResolver` should be a pure `resolveConfig(config, secretSource) → resolvedConfig` function, not a stateful resolver that reaches global env.** Walk a config object, replace every `${secret:name}`, throw `SECRET_MISSING`/`SECRET_HANDLE_INVALID` on the first bad handle. The env/`LoadCredential` load is a *separate* source object handed in — keeps the resolver a pure UT and the source loader a thin adapter.
- **`ProviderProfile` is the single source of truth shared with the ARCH-008 alias validator.** Fields `{supportsExtendedThinking, supportsToolUse, timeoutMs, retries, effortMapping}`. The validator reads the same table it feeds the builder — one row per alias, no second copy. Retires the open `effort`-mapping question as a config row.
- **ARCH-019 contract — expose the predicate, not just the assert.** The realized `assertWorkRootIsolated(workRoot, existsImpl): void` throws-or-returns. Boundary/testability (below) both want a **pure `findProjectMarkerAncestor(path, existsImpl) → string | null`** underneath it, so the same predicate is reusable at session-init (finding #3) without the throw, and its truth table is unit-testable directly. Keep `assertWorkRootIsolated` as the thin boot-time throwing wrapper over it. The typed error `WORKROOT_INSIDE_PROJECT` already names the offending ancestor + remedy (REQ-021 c2) — good; keep that shape.
- **Contract gap — `mcp_provision`'s "admin-only" authority is not in its signature.** It is enforced *only* by network position (D-BIND loopback). The tool's contract should state this precondition explicitly and refuse to serve when `bind != loopback` even if `insecureNoAuth:true` is set for the general listener — an RCE-provisioning write authority deserves a stricter default than a read.

### Boundary/error lens
- **(#1) Slot free-exactly-once on the kill path.** D-DOS rations a *process-global* semaphore slot per agent; D-KILL kills the CLI child (via `Options.abortController`) on timeout. Failure surface: (a) the timeout branch frees the slot AND the query promise later settles and frees it again → **double-free**, caps silently exceeded; (b) abort throws / child already exiting and the free is only on the query-settle path → **never-free**, a hung provider starves the resource the semaphore rations. **Design requirement:** acquire in the RunGuard, release in a single `finally` keyed to the *race outcome*, idempotent (guard flag), covering success / schema-retry-exhausted / provider-error / timeout-abort / stop / suspend. One release site, provably once. UT with an injected semaphore (max=1) asserting count returns to 0 on every branch. Note the realized code registers `onExternalAbort` with `{once:true}` and a `setTimeout` timer — the DES must also specify **timer + listener teardown in the same `finally`** so a settled-before-timeout call doesn't leave a live timer that later aborts a *reused* controller.
- **(#2) Redaction is a capture-time boundary, not a post-filter.** REQ-018 says resolved values never enter transcripts/dashboard/logs. Secrets are injected into the *config the parent hands the SDK* — including a stdio-MCP child's argv/env — and the AgentTranscriptSink taps the raw SDK stream. **Design requirement:** a pure `redact(event, secretValues) → event` in the capture path, applied before any write to `agent-<id>.jsonl`; `SessionInitRecord` logs secret **handle names only**. Invariant UT: given a config with `${secret:x}`, no byte of the resolved value of `x` appears in the transcript or init record. Distinct from "the sandbox can't read the proxy config file" (the ARCH-016 filesystem half) — both needed, neither substitutes.
- **(#3, NEW, HIGH-adjacent) ARCH-019 is a point-in-time boot check against a tree that mutates during runs.** `main.ts` calls `assertWorkRootIsolated` **once at boot**; session-init (`claude-agent-sdk-client.ts:357`) then sets `cwd: req.workspace` with `settingSources:['project']` and **re-runs no isolation check**. Boot guarantees workRoot + ancestors are marker-free, but the run-workspace subtree *below* workRoot is written by agents during runs. Concretely: agent A (steered by untrusted data it is processing) writes `./CLAUDE.md` (or a `.git` dir) into its run workspace; a later `agent()` in the same run/workflow is spawned with `cwd` at that workspace → the CLI's project-root resolution treats the agent-authored marker as the project and loads its `CLAUDE.md` into agent B's context — the **exact REQ-021 leak, at session-init, below the tool-call jail**, re-opened *after* boot. The ARCH-016 realpath/`Bash`-deny callback never sees it (session-init, not a tool call — the very bypass ARCH-019 exists for); the ARCH-019 boot check never sees it (dynamic). **Cross-run persistence is blocked** *iff* the ARCH-016 confinement truly prevents an agent writing above its run workspace into the shared per-workflow work folder (REQ-013 roots agent I/O at the run workspace, so this should hold — the DES must state it as the load-bearing precondition). The residual **intra-run/intra-workflow variant remains open**. **Design requirement (minimal):** at session-build, re-run the pure `findProjectMarkerAncestor` from the run-workspace `cwd` **up to (excluding) workRoot** and, on a hit, refuse the build with a typed error (or plant an engine-owned project boundary so the CLI cannot climb past the run workspace). This is the *same pure predicate*, not a new subsystem — it is the minimum that makes REQ-021's invariant true against a runtime-mutable tree, exactly parallel to the D-SEC ruling that a check which is true only at one instant "under-builds a stated invariant." Ranked MED-HIGH pending an empirical confirmation of whether the CLI loads a marker at/inside `cwd` (REQ-021 itself was found empirically — this variant deserves the same one real repro).
- **(#4) Fail-safe `ProviderProfile` default.** An alias with no profile row must default to `supportsExtendedThinking:false` and conservative `supportsToolUse`, because the D-F6 defect was *defaulting thinking on*. Ideally caught at submission (`ALIAS_PROFILE_MISSING`), but if it reaches the builder the default must not 400 a non-reasoning model. Fail-safe default > fail-open default.
- **(#5, NEW) ARCH-019 must canonicalize with `realpath`, not `resolve`.** `assertWorkRootIsolated` does `let dir = resolve(workRoot)` — `resolve` only normalizes `.`/`..`, it does **not** follow symlinks. A workRoot that is a symlink whose target is inside a git repo, or whose ancestor chain crosses a symlink into a project, passes the boot guard while the CLI (which operates on the real path) still climbs into the project. This is inconsistent with ARCH-016's own **realpath-based** confinement callback (D-SEC). **Design requirement:** `realpathSync` the resolved workRoot before the ancestor walk; keep the fs-probe injected so the UT can model a symlink→project layout. (Boundary case, cheap fix; MED because it needs an attacker/operator to place a symlink, but it is a silent bypass of a fail-closed guard.)
- **(#6) `isLoopback(bind)` predicate, not string equality.** Must accept `127.0.0.0/8` and `::1`, reject everything else, not be foolable by `127.0.0.2`. `bind !== '127.0.0.1'` is simultaneously a false-reject (breaks a legitimate `::1` deploy) and, if "fixed" with a prefix match, a bypass. One tested predicate.
- **(#7) Atomic secret resolution.** Resolve the *whole* config or throw; never inject a partial config. Mixed good/missing handles → fail the build with `SECRET_MISSING`, nothing spawned. Boundary UT proves it.
- **(#8, NEW) The REQ-021 guarantee is coupled to `settingSources` never widening past `['project']`.** The workRoot guard prevents the *project* CLAUDE.md/memory leak; it does **nothing** about a global `~/.claude/CLAUDE.md`, which loads only if `settingSources` includes `'user'`. The realized code excludes `'user'/'local'` (`settingSources: req.workspace !== undefined ? ['project'] : []`) — correct today, but that is the *only* thing standing between the operator's global memory and every agent's context, and it is enforced by a ternary, not a test. **Design requirement:** a regression-guard UT asserting the built `SDKOptions.settingSources` never contains `'user'` or `'local'` on any path, so a future edit that adds `'user'` to load some user-global skill can't silently re-open a leak the workRoot guard, by construction, cannot catch. (LOW severity today, but it is a one-line invariant guarding a whole class of leak.)
- **Runtime-dead MCP is a distinct failure mode from `MCP_NOT_PROVISIONED`.** A provisioned-and-live MCP can die before the run → surfaces as a tool failure → `FailureEnvelope{kind:tool_error}` → `agent()` null (matches REQ-003). Acceptable, but the design must *say so* so it isn't mistaken for a silent no-op. Do **not** mint a new public reason code (see conflict C2); keep it in `FailureEnvelope.kind`.
- **Reason-code completeness** against REQ-016..021: `MCP_NOT_PROVISIONED`, `MCP_PROBE_FAILED`, `SECRET_MISSING`, `SECRET_HANDLE_INVALID`, `HOOKS_UNSUPPORTED`, `PROVIDER_TIMEOUT`, plus the boot-time `WORKROOT_INSIDE_PROJECT` (ARCH-019). Add `ALIAS_PROFILE_MISSING` (submission-time, from #4). `WORKROOT_INSIDE_PROJECT` is a **boot/entrypoint** error (fail-to-start), not a per-run client-envelope code — keep that distinction explicit; it never reaches a workflow caller. Everything finer lives internal in `FailureEnvelope`.

### Testability lens
- **Timeout must ride the injected Clock, not real ms.** REQ-020's race must use the v2 injected Clock/Ticker (DES-016) or the UT waits the CLI's real ~4-minute backoff. Assert the race resolves `null` at simulated `timeoutMs` with the child aborted.
- **Kill is an injected `spawnImpl`/abort seam, asserted once.** You cannot unit-test aborting a real `claude` CLI child, so the abort target must route through the seam; UT asserts abort called exactly once on timeout and the slot freed exactly once.
- **`McpProbe` injected into `mcp_provision`.** UT: fake prober returning dead → `MCP_PROBE_FAILED`, nothing persisted; live → row persisted.
- **The global semaphore must be an injected instance, not a module-level `static`.** Construct **one** instance at the composition root, pass by reference into every RunGuard — same object (true global rationing), still injectable/resettable (UT builds one with max=2, asserts the 3rd agent queues). Never a `static`/singleton-module global.
- **ARCH-019 is almost entirely pure UTs — keep it that way.** `assertWorkRootIsolated` already injects `existsImpl` — good. The truth table to lock: (a) marker at workRoot itself → throws naming workRoot; (b) marker at a mid ancestor → throws naming that ancestor; (c) `.git` as *file* vs *dir* → both trip (existsSync handles it — assert both); (d) clean chain to fs-root → returns/void, **no false positive** (REQ-021 c3); (e) `~/.claude` present but no `.git`/`CLAUDE.md` → does **not** trip (the realized comment claims this — pin it with a UT); (f, from #5) a symlinked workRoot into a project → trips only once `realpath` is added (UT models it via the injected probe + an injected realpath). The boot wiring (`main.ts`) is a thin composition-root UT: injected probe reporting a marker → boot throws; clean → boot proceeds. The **session-init re-walk (#3)** and the **settingSources invariant (#8)** are likewise pure UTs over `findProjectMarkerAncestor` and the built `SDKOptions` — no live model, no real project tree needed.
- **Secret-never-in-artifact and curated-allowlist-observable are pure UTs** over `SessionInitRecord` + `redact`. Only the real `tool_use` round-trip against local Ollama needs the real tier.

## Task-split guidance (feeds the synthesizer's 03-tasks)
Split along the test seams so "every DES coverable by a UT" stays honest — never merge a pure and an impure half into one task:
- **ARCH-017 → three tasks:** (a) pure builder + `ProviderProfile` table + validator wiring (all pure UTs, incl. thinking-disabled, curated allowlist, strict-MCP, fail-safe default, **the settingSources-never-user/local invariant #8**, **and the session-init project-marker re-check #3** — it belongs to the builder because the builder owns `cwd`/`settingSources`); (b) impure timeout-race + abort-on-timeout + slot free-exactly-once + timer/listener teardown over injected clock/spawn/semaphore; (c) the one real-tier Ollama `tool_use` round-trip (VAL). Merging (a) into (b) forfeits the master seam.
- **ARCH-015 → two tasks:** (a) registry CRUD + typed `MCP_NOT_PROVISIONED`/`MCP_PROBE_FAILED` + strict-MCP referenced-by-name injection (store UTs); (b) `McpProbe` wiring at provision (injected-probe UT).
- **ARCH-016 → two tasks:** (a) pure `resolveConfig` + `redact` (pure UTs, atomicity, redaction); (b) env/`LoadCredential` source loader + parent-only filesystem containment callback (the realpath/arg-complete/`Bash`-deny hardening).
- **ARCH-019 → one small task, kept pure:** extract `findProjectMarkerAncestor(path, existsImpl, realpathImpl) → string|null`; `assertWorkRootIsolated` becomes the throwing boot wrapper; add the `realpath` canonicalization (#5); wire boot fail-fast (`main.ts`). All pure UTs (truth table above). The **session-init re-walk (#3)** rides ARCH-017(a), reusing this predicate — do not duplicate the walk. Do NOT build a per-run OS jail (D-SEC/D-WORKROOT: no new runtime subsystem).
- **D-DOS / D-BIND / D-PROC** are amendments to existing modules (RunGuard / ARCH-009 / ARCH-005+017), each a small tightly-scoped task with its own boundary UT (semaphore count-returns-to-zero; `isLoopback` truth table; port-selection + SIGTERM→SIGKILL + temp-dir cleanup).

## Risks
- **R1 (HIGH) — semaphore slot double-free / never-free on the abort path.** Caps silently violated (double-free) or a hung provider starves all runs (never-free). Mitigation: single idempotent release site keyed to race outcome + timer/listener teardown; UT count-returns-to-zero on every branch. (D-KILL's "REQ-020 passes its test while budget silently rots.")
- **R2 (HIGH) — secret leak via the transcript tap** before redaction, or via a stdio-MCP child's argv in the SDK event stream. Mitigation: capture-time `redact`, handle-names-only `SessionInitRecord`, invariant UT.
- **R3 (MED-HIGH, NEW) — ARCH-019 boot-only check re-opens the REQ-021 leak at runtime.** An agent writes a `CLAUDE.md`/`.git` marker into its run-workspace subtree → the next same-run `agent()` session-init loads it, below every tool-call jail. Mitigation: session-init re-walk from `cwd` up to workRoot using the same pure predicate; state the ARCH-016-confinement precondition that blocks the cross-run variant; one real repro to confirm the CLI's at-cwd marker behavior. **Escalates to HIGH if the per-workflow work folder turns out writable by runs** (cross-run persistence).
- **R4 (MED) — unprofiled-alias thinking default re-opens the D-F6 Ollama 400.** Mitigation: fail-safe default + submission-time `ALIAS_PROFILE_MISSING`.
- **R5 (MED, NEW) — ARCH-019 `resolve`-not-`realpath` symlink bypass.** A symlinked workRoot/ancestor into a project silently passes the fail-closed boot guard. Mitigation: `realpath` before the ancestor walk (consistency with ARCH-016).
- **R6 (MED) — `isLoopback` string-compare false-reject/bypass.** Mitigation: one tested predicate over `127.0.0.0/8` + `::1`.
- **R7 (MED) — partial (non-atomic) secret resolution fails open** on REQ-018's core invariant. Mitigation: resolve-whole-or-throw.
- **R8 (LOW, NEW) — REQ-021 guarantee silently coupled to `settingSources:['project']`.** A future edit adding `'user'` re-opens the global-memory leak the workRoot guard cannot catch. Mitigation: regression-guard UT asserting `settingSources` never contains `'user'/'local'`.
- **R9 (LOW) — builder purity erosion** (env read inside the "pure" builder) silently degrades the whole slice's UT economics. Mitigation: purity invariant UT; ban env access in review.
- **R10 (LOW) — `mcp_provision` write authority equated with a read on the no-auth listener.** Mitigation: stricter default (refuse when `bind != loopback` even with `insecureNoAuth`).

## Expected disagreements with the other lens (quality-dimensions: observability / replaceability / consumability / self-sustainability)
- **ProviderProfile: config table vs provider SPI.** Quality/replaceability will push toward a formal provider plugin/SPI. I hold the Karpathy line (D-PROFILE resolved): a **flat config table**, one row per alias. GLM/qwen is a config row.
- **Subprocess lifecycle: in-process supervisor vs supervisor-owned restart.** Quality/self-sustainability may want a `ManagedSubprocess` watchdog. I side with D-PROC: **minimal in-process cleanup only** (port selection, health probe, SIGTERM→SIGKILL, temp-dir + abort-on-timeout slot free), **restart/recovery stays on systemd/docker**. Expect a boundary argument about exactly where that line sits.
- **Discoverability vs redaction on the no-auth listener.** Quality/consumability will want `list-provisioned-MCPs` / `list-secret-names` endpoints for agent UX. My boundary/security lens refuses enumeration on the unauthenticated listener (D-REDACT): a **clear typed error to the submitter, no inventory enumeration** until REQ-012 auth lands. Expect the sharpest disagreement here.
- **`SessionInitRecord` richness.** We agree it should exist and be rich (agent-altitude observability). We disagree on contents: quality may want the resolved effective config for debuggability; I insist **handle-names-only, redacted values, plus the resolved `cwd`/`settingSources`/project-root decision** (so REQ-021 confinement is auditable from the store) — observability must record the *decision*, never the *secret*.
- **ARCH-019 scope: boot-check-is-enough vs runtime re-check (NEW, likely a same-group + cross-group tension).** Quality/self-sustainability may accept the boot check as "the minimum D-WORKROOT sanctioned" and read my session-init re-walk (#3) as scope creep against "no new runtime subsystem." My boundary line: it is the *same pure predicate at a second call site*, not a subsystem, and it is the minimum that makes the invariant true against a runtime-mutable tree — under-building an invariant is a defect, not a Karpathy win (the exact logic the panel already accepted for D-SEC's lexical-check ruling). Expect this to be argued.
- **Global semaphore default value.** A scalability-leaning reviewer may argue the `min(16,cores-2)` default; I care far more that it is **injectable and count-provable** than about its number.

## Internal conflicts within my own group (surfaced per the debate mandate)
- **C1 — Interface-contract ⟂ Testability on the global semaphore.** Contract wants "one process-global counter"; testability wants an injectable, resettable instance. **Karpathy resolution:** one instance built at the composition root, passed by reference — same object, injected seam, no `static` global.
- **C2 — Boundary/error ⟂ Interface-contract on reason-code granularity.** Boundary wants a distinct public code per failure mode; consumability wants a small stable enum. **Karpathy resolution:** keep the **small published taxonomy** on the client envelope; finer distinctions live in the internal `FailureEnvelope.kind/providerDetail`. `WORKROOT_INSIDE_PROJECT` is boot-time (fail-to-start), never a per-run client code — a separate axis, not a taxonomy addition.
- **C3 — Boundary/error ⟂ simplicity on kill lifecycle.** Boundary wants full lifecycle guarantees (abort, reap, free slot, teardown timer/listener, attribute partial tokens, cleanup temp dir); D-PROC says "no in-process watchdog." **Resolution:** minimal per-agent cleanup (abort + finally-free-slot + timer/listener teardown + temp-dir rm) *is* warranted (incurred debt, orphan burns tokens/slot); broader self-heal stays on the supervisor. Line: "one agent's resources" (in-process) vs "the process" (supervisor).
- **C4 — Testability ⟂ Interface-contract on redaction.** To unit-test "no secret in transcript" you need capture to be a pure function of `(event, secretValues)`; the live SDK stream is async. **Resolution:** a pure `redact(event, secretValues)` sits in the tap — unit-testable alone; live capture just applies it.
- **C5 — Boundary/error ⟂ Karpathy simplicity on ARCH-019's second call site (NEW).** Boundary (me) wants the session-init re-walk (#3) + `realpath` (#5) + the settingSources invariant (#8); simplicity (and D-WORKROOT's stated "one boot check + a cwd invariant, no new runtime subsystem") wants to stop at the boot check. **Resolution:** the boot check covers the *primary, empirically-reproduced* case (the operator's own project); it is correctly minimal for that. The three additions are **not a new subsystem** — they are the *same pure predicate at session-build* (#3), a one-line canonicalization (#5), and a one-line assertion (#8). Each closes a way the *stated* REQ-021 invariant is presently only instantaneously-true. I concede the OS-jail alternative stays cut (D-SEC); I hold that "true only at boot" under-builds "no ambient project leaks into agent context," and rank the runtime re-walk MED-HIGH precisely so the synthesizer can weigh it against a confirmed real repro rather than accept a boot-only guarantee on faith.
