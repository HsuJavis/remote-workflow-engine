# Design panel — Adversarial group (r1, independent)

**Stage:** Detailed Design (Gate 3/4 merged), iteration **v2** (ARCH-010..014 / DES-016..023 / TASK-019..027).
**Lenses carried (traded off explicitly):** (a) Interface-contract, (b) Boundary/error, (c) Testability.
**Tie-break:** Karpathy simplicity-first (minimum design that solves the REQ; no speculative flexibility).
**Round:** 1 (independent proposal — I argue from my lenses and surface conflicts; the synthesizer reconciles).
**Model contract:** claude-opus-4-8. Scope = v2 extension modules only; the v1 kernel (DES-001..015) is DONE and real-validated — I extend its contracts (one `ResultEnvelope`, one injected `Clock`, injectable ports) and flag where v2 must not violate them.

## Altitude judgment (system vs agent)
From `tech_stack` + REQs this is **both**, and v2 splits cleanly by module — apply the fitting altitude per module, don't force the other:
- **Conventional-system altitude:** Scheduler (DES-016/017), Dashboard HTTP (DES-018), Deploy/hardening (DES-022) — ordinary timer/observability/packaging engineering; the interesting content is Clock-injectability and missed-fire/restart/orphan-process boundaries.
- **AI-agent altitude:** Asset Sync (DES-019/020) and the client plugin/guidance skill (DES-021) — they mutate *agent runtimes* (skills/hooks/MCP tool surface the SDK sessions see) and teach *agents* how to consume the service. The **recursion guard (D4)** is literally "this agent system must not let its own remote agents re-invoke it"; the guidance skill is *consumability by an agent, not a human*.
Cost/self-sustainability at the agent altitude is the axis v2 most under-serves (R1): scheduled + resident runs drive **paid multi-provider agent() calls** on an unattended timer. I apply both altitudes and do not force the irrelevant one (no agent-observability ceremony on Deploy; no human-UX polish on the recursion guard).

## Summary
The v2 seam choices are largely right and I endorse the load-bearing ones: the DES-016/017 **CRUD-vs-pure-firing-engine split**, the **pure `tick(now)`/`computeNextFire` + injected Clock+Ticker** testability seam, the **read-only poll-the-RunStore dashboard with no event bus**, the **no-parallel-DTO** `buildDashboardModel`, and the **injected `McpProbe`** isolating the one network dependency. Those satisfy my testability lens without over-injection (C3 discipline holds: inject only nondeterministic/networked/timed seams; keep cron math a concrete pure dependency).

My independent objections concentrate where the design **over-claims purity, under-specifies boundaries, or omits cost containment** on an explicitly no-auth (D5) surface:
1. The two "pure security predicates" in DES-019 (`safeRelPath`, `isSelfReferential`) cannot deliver the containment they promise from strings alone (symlink escape; `localhost≡127.0.0.1≡hostname` self-ref). On a no-auth service where `asset_push` is already code-exec, path-containment is the *last* boundary and must not be a leaky string check.
2. Scheduled/resident runs carry **no budget field** and default to unbounded spend — a nightly cron against paid providers is a runaway-cost hole (agent-altitude self-sustainability), and overlap-allowed compounds it.
3. Several boundaries are unspecified: cron **default timezone** (DST determinism), dashboard **XSS-escaping of untrusted model output**, asset **size/count caps**, probe **bounded timeout + npx-at-push-time exec surface**, transcript **pagination**.
Plus one task-split defect: TASK-019's "no clock needed" contradicts DES-016 computing `nextFire` at `create`.

## Key points (by lens)

### (a) Interface-contract
- **KP-1 — Close the `ErrEnvelope.code` set.** Every v2 tool returns `ResultEnvelope`/`ErrEnvelope{code,message,field}` (good, uniform). But `code` is a free-form string. Define a **closed union** of codes (`SCHEDULE_DISABLED|SCHEDULE_NOT_FOUND|WORKFLOW_NOT_FOUND|CRON_INVALID|AT_UNPARSEABLE|MCP_UNSUPPORTED|MCP_UNREACHABLE|PATH_ESCAPE|SELF_REFERENTIAL|ASSET_TOO_LARGE|...`). The one cheap move that satisfies *both* my contract lens (uniform envelope) and the boundary taxonomy an agent caller needs to branch retryable-vs-terminal. (Resolves internal conflict #2.)
- **KP-2 — `SchedulerPort.originOf` is sync while every sibling returns `Promise`.** Legit if it reads `better-sqlite3` synchronously, but the mixed sync/async surface is an avoidable contract wart; make it `Promise<...>` or document why it is the one sync method.
- **KP-3 — `trigger` semantics are ambiguous.** `trigger(workflow, args)` is keyed by workflow name, but the only failure named is `SCHEDULE_DISABLED`. Specify: does `trigger` require an *enabled resident Schedule record* (then unknown/none → `SCHEDULE_NOT_FOUND`), or is it "run any registered workflow now" (then `resident` as a Schedule kind is nearly vestigial — KP-4)? Pin the precondition and the `WORKFLOW_NOT_FOUND` vs `SCHEDULE_DISABLED` split.
- **KP-4 — Is `resident` a real Schedule kind or just `enabled` on the catalog entry?** (Karpathy.) A `resident` record carries only `{id,workflow,enabled}` — no time field; its whole job is to gate `trigger` behind an enable flag that could live on the Catalog entry. I don't insist on removing it (one Schedule union is simpler than a split store), but the synthesizer should justify why `resident` earns its own record rather than leaving it apparent dead weight.
- **KP-5 — Pin cron/tz types.** `computeNextFire(cron, tz, after)` — name the cron dependency and require `tz` to be an **IANA zone string**, default **`UTC`** when absent. Unpinned tz default = nondeterministic firing and untestable DST behavior (also KP-9 testability).
- **KP-6 — Transcript endpoints return `TranscriptEvent[]` whole.** No `limit`/`cursor` on `workflow_agent_log` or `/api/runs/:id/agents/:aid`. A long agent run yields an unbounded array; add pagination to the contract now — retrofitting a paged contract later is a breaking change.

### (b) Boundary/error
- **KP-7 — `safeRelPath` cannot be a *pure string* symlink guard.** DES-019 claims a pure `safeRelPath(p, root)` rejects `..`/absolute/**symlink-y** paths. String normalization catches `..`/absolute, but a symlink is a *filesystem* property: a component that is (or resolves through) an existing symlinked directory in the asset root redirects the write outside root, invisible to the string. TOCTOU/containment hole. **Fix:** keep the pure predicate as the fast first gate, but add an **impure write-time guard** (`fs.realpath` of the resolved target must be a prefix of the realpathed asset root, or open with `O_NOFOLLOW` per component). On a no-auth service (D5) where `asset_push` already = code exec, path-containment is the last line — it must hold on disk, not just in a testable string function. (Internal conflict #1.)
- **KP-8 — `isSelfReferential` string-compares endpoint to `selfBind` → under-rejects.** `localhost` vs `127.0.0.1` vs `0.0.0.0` vs the host's LAN IP vs a tunnel hostname all denote "this server," but a string compare misses them → the D4 recursion guard silently fails and a remote agent *can* re-invoke this service. Normalize (resolve `localhost`→loopback set; treat any bind-equivalent addr as self). This makes the predicate partly impure (addr resolution) → same two-tier resolution as KP-7. Under-rejection here is worse than the over-rejection the lookalike fixture guards against.
- **KP-9 — Scheduler cost/overlap containment (agent-altitude, self-sustainability).** `Schedule` has **no `budget` field**; scheduled/resident runs hit `RunManager.start` with default/`null` budget → **unbounded token spend on an unattended timer** against paid providers. Overlap-allowed (a slow cron piling independent runs) multiplies it. Add optional `budget` to every Schedule arm (defaulting from a server-level cap) and document a max-in-flight-per-workflow guard, or at minimum surface the overlap+cost interaction as an explicit accepted risk, not silence. Single highest-value boundary gap and it is *agent-system-specific*.
- **KP-10 — `setEnabled`/`delete` on unknown id, and `create` dup.** Unspecified → must return `SCHEDULE_NOT_FOUND` (never throw across the tool boundary). Define whether `create` of a duplicate logical schedule is allowed (id is server-minted, so silent dupes are possible).
- **KP-11 — Probe is a bounded, dangerous operation.** `McpProbe.probe` of an **npx-stdio** config *spawns `npx <pkg>`* = installs+runs an arbitrary npm package **at push time**, before any run, on a no-auth server — it pulls code-exec *forward* from run-time to validate-time. It also needs a **bounded timeout** (same breaker discipline as the gateway, else a hung handshake hangs the tool). Neither is stated. Minimum: bounded timeout on probe; document (and tunnel-gate) that probe itself executes untrusted package code. Strengthens the drop-the-probe call (D-1).
- **KP-12 — Dashboard renders untrusted model output → stored XSS.** The `GET /dashboard` HTML page (DES-018 route-back) injects run/agent/transcript data — which includes **model-produced text and tool args** — into the browser. On an unauthenticated dashboard, an agent whose output contains `<script>` yields stored XSS. The VM builder is pure/safe, but the renderer must **escape all agent-produced content**. Add a boundary invariant + UT/real-tier assertion (push a `<script>`-bearing transcript, assert escaped).
- **KP-13 — Asset size/count caps.** v1 caps the script at 512 KB; assets have **no size or file-count cap** (`contentB64` decoded into memory, written to disk). Add per-file and per-push caps (`ASSET_TOO_LARGE`) — DoS/disk-fill boundary on a no-auth service.

### (c) Testability
- **KP-14 — Endorse the firing-engine seam.** DES-017's pure `tick(schedules, now)` + `computeNextFire(...,after)` + injected `Clock`/`Ticker` (FixedClock+FakeTicker, zero wallclock waiting) is exactly the adversarial ask; missed-fire/catch-up become table-driven UT. No change requested — this is the model the whole scheduler should be judged against.
- **KP-15 — Task-split defect (TASK-019 vs DES-016).** TASK-019's note says "**No clock needed** (pure CRUD + immediate trigger)," but DES-016 has `create` validate and (via `ScheduleStatus.nextFire`) compute the next fire, and `list` returns `nextFire`/`lastFire` — all **clock-derived**. The 019/024 split cuts *through* `nextFire` computation. Resolve one of two ways: (i) `create` stamps only raw fields and defers all `nextFire` computation to the firing engine (TASK-024) so 019 is genuinely clockless; or (ii) TASK-019 also takes the injected `Clock`. Silent as-is, the seam yields a bare-`Date.now()` in CRUD — the exact Exit-Gate-5 violation DES-014 forward-flagged.
- **KP-16 — Guard against over-injection.** Do **not** inject the cron parser or the base64 codec — deterministic pure dependencies with no nondeterminism to isolate (violates C3). Inject only `Clock`, `Ticker`, `McpProbe`, `RunStore`. (Internal conflict #3.)
- **KP-17 — Symlink/self-ref need a real-FS/real-net test, not only pure-predicate UT.** Consequent to KP-7/KP-8: add a tmpdir-with-planted-symlink integration test and a `localhost`-vs-`127.0.0.1` self-ref case at real-tier to DES-023's REQ-009 path explicitly. The pure UT alone passes while the real hole stands.
- **KP-18 — Namespace-collision test must be concrete (DES-021).** "MCP tool namespace must not collide with the local dynamic Workflow tool" needs an actual assertion: enumerate the remote `workflow_*`/`schedule_*`/`asset_*` names and assert disjoint from the local tool's names — otherwise it is an untestable claim.

## Risks
- **R1 — Runaway cost on unattended agent runs (HIGH, agent-altitude).** No schedule-level budget + overlap-allowed + paid multi-provider routing = an enabled nightly cron can spend without bound with no human present. KP-9. The risk most specific to this being an AI-agent system.
- **R2 — Path/self-ref containment is the last boundary on a no-auth service and is currently a leaky string check.** KP-7/KP-8. If either under-holds, `asset_push` (already code-exec) escapes the workspace or the D4 recursion guard fails open. HIGH given D5.
- **R3 — Probe = validate-time RCE via npx.** KP-11. Tunnel-gating (C4) mitigates but does not remove; argues for dropping the probe (D-1).
- **R4 — Stored XSS on the unauthenticated dashboard from model output.** KP-12. MEDIUM (needs a hostile/naive agent) but trivial once present.
- **R5 — DST/tz nondeterminism.** KP-5. Unpinned tz default makes cron firing and its UTs environment-dependent.
- **R6 — Exit-Gate-5 regression via the 019/024 split.** KP-15. A bare `Date.now()` sneaks into CRUD.

## Expected disagreements

### With my own three lenses (internal conflicts — surfaced per the lens brief)
- **#1 Testability/simplicity ⟂ Boundary-completeness (predicate purity).** Testability wants `safeRelPath`/`isSelfReferential` pure and UT-covered both directions; boundary says a pure string function *cannot* enforce symlink/self-ref containment. **Tie-break (Karpathy-consistent):** two-tier — pure gate first (fast, fully UT'd) **plus** an impure realpath/addr-normalize guard at the FS/network edge (integration+real-tier). Purity is not worth a containment hole on a no-auth service. (KP-7, KP-8, KP-17.)
- **#2 Interface-contract uniformity ⟂ Boundary taxonomy.** One `ResultEnvelope` for all (contract) hides retryable-vs-terminal distinctions (boundary). **Tie-break:** keep the single envelope but make `code` a **closed union** — cheap, satisfies both. (KP-1.)
- **#3 Testability (inject seams) ⟂ Simplicity (don't).** **Tie-break:** inject only nondeterministic/networked/timed seams (Clock/Ticker/McpProbe/RunStore); the cron parser and codec stay concrete. (KP-16.)

### With the quality-dimensions group (observability/replaceability/consumability/self-sustainability)
- **D-1 — Live MCP probe: I push to DROP it for v2; quality (and REQ-009) will keep it.** Static `classifyTransport` already rejects non-runnable kinds; the live probe adds a network+**npx-exec** dependency and an RCE-at-push-time surface on a no-auth service for marginal value (a momentarily-unreachable-but-runnable config just fails at run time, where the gateway breaker already yields `null`). My r1 position: **static-only**; if the REQ mandate wins, **injected + hard-bounded-timeout** is the floor (KP-11). *(I expect convergence to keep-but-inject; recording the independent drop-call is the point of round 1.)*
- **D-2 — Catch-up policy: fire-once, never backfill.** Quality's self-sustainability instinct is durable backfill of every missed slot ("never miss a job"). I oppose: backfill storm = many concurrent runs = R1 cost blowup. Fire-once-on-catch-up (cron) / fire-immediately (one-shot) delivers equal REQ-015 satisfaction, simpler and boundary-safe.
- **D-3 — Run-origin observability without touching v1.** Quality will want `triggeredBy` threaded into the journal/`RunSpec`; that is v1 rework (boundary: v1 signature change). I prefer the scheduler owning a `scheduleId→runId` join and `originOf(runId)` deriving origin — zero v1 rework, observability goal still met.
- **D-4 — Asset drift: push-time probe only, no lazy re-probe.** Quality may want on-first-use re-probe for drift; I resist extra outbound traffic/exec on an unauthenticated (D5) service. Defer re-probe to v3 (post-auth); document drift as a known boundary.
- **D-5 — Dashboard liveness: poll the RunStore port, no event bus.** Quality may want a push event-bus for lower latency; polling reuses the established injectable test seam and keeps the design minimal (testability + simplicity align). Agree with the current design against a bus.
- **D-6 — GatewayClient parity: document, don't build a v2 contract-test.** Quality flags the two impls drifted; a parity contract-test touches v1 code (out of zero-rework v2 scope). Document the sdk-path-primary decision; no new DES.
- **Agreement with quality:** machine-readable error `code`s and real `TOOL_METADATA.inputSchema` for the new tools — I extend it (closed code union, KP-1) rather than dispute it.
