# Review — Adversarial Architecture Group (security / scalability / testability)

- **Stage:** iso-agile-sdlc review (re-review after the Gate-8 v2 route-back, IMPL-064 / D-V2G8-1..2, IMPL-065/066).
- **Lens:** Adversarial architecture — (a) security, (b) scalability/performance & consistency, (c) testability; Karpathy simplicity-first as tie-breaker. The three lenses conflict; I surface it per finding.
- **Compared:** `02-architecture.md` (ARCH-001..014, cross-component invariants INV, decision rationale D-*/C1..C4) vs `06-impl-log.md` (IMPL-001..066) and the source files those IMPLs list (scoped to this iteration).
- **Verdict:** NOT consistent — 5 architecture deviations (3 MEDIUM, 2 LOW). No HIGH remains open: the prior HIGH (V3) was materially reduced by IMPL-064 but a residual MEDIUM survives.

**Prior-round findings now RESOLVED (verified in source):**
- *Prior V2* (stale `assertBudget` pre-check → unbounded overshoot) — fixed by D-G8-6 (`RunGuard.reserve/releaseReserved`, `run-guard.ts:92-104`; `run-manager.ts:331,338,378`). The over-correction it introduced was itself walked back — see V4 (now LOW).
- *Prior V3 headline (HIGH)* — the `agent()` CLI ran `permissionMode:'bypassPermissions'` with `Bash` in the default tool set and `cwd`-only confinement, letting the untrusted script drive a fully-privileged shell in the parent trust zone. IMPL-064 (D-V2G8-1) closed the *default* hole: `permissionMode:'default'` (`claude-agent-sdk-client.ts:261`), `Bash` dropped from `BUILT_IN_CORE_TOOLS` (`:118`, now `['Read','Write']`), and a `canUseTool` workspace-boundary callback (`:140-148,262`). **The residual is now MEDIUM — see V3 below** (the callback does not cover the opt-in `Bash` path, symlinks, or non-`file_path` file tools, so ARCH-007's confinement INV is still not a general property).
- *Prior V5 env-leak* (full `process.env` forwarded to the spawned CLI) — fixed by D-G8-5 (`ENV_ALLOWLIST` / `buildSubprocessEnv`, `claude-agent-sdk-client.ts:167-181`).

The sharpest remaining tension is still the trust-boundary: the process split (D6/C1) is honored for the *orchestration child* (no keys/network/fs there), and the default `agent()` surface is now confined — but the confinement INV is enforced only for two file tools' literal path arguments, so an agentType that opts into `Bash` (still fully supported) re-opens the exact cross-run / host-secret reach the architecture says the trust split contains.

## V1 — ARCH-009 / ARCH-001: the auth-middleware seam still does not exist (carried, unresolved)
- **Severity:** MEDIUM
- **Violated:** ARCH-001 note ("no auth *decision* — calls the ARCH-009 seam, a no-op in v1"); ARCH-009 ("Wraps the ARCH-001 request pipeline; ships v1 as a pass-through no-op … **No ARCH-001 signature change → drop-in**"); rationale ("extensions attach at pre-existing v1 seams — auth-as-middleware — with **zero v1 rework**"); C4.
- **Evidence:** `src/server.ts:471-521` — the `createHttpServer` handler dispatches `/dashboard` → `/api/runs*` → `/mcp` (`readBody` → `JSON.parse` → `callTool`) with **no** auth middleware, pass-through hook, or wrapper between transport and facade. The container diagram's `CC → E1(ARCH-009) → K1` edge has no code counterpart.
- **Failure scenario / why it matters (adversarial):** the C4 bet — "v2 `asset_push` RCE is acceptable pre-v3 because auth drops in with zero rework" — depends on the no-op seam existing today. As built, v2 added *three* unauthenticated surfaces on the same open listener (`GET /dashboard` `:476`, `GET /api/runs*` `:483`, and the RCE-capable `asset_push` reachable via `POST /mcp` `:507-511`), and v3 OIDC will require surgery on `createServer()`'s request pipeline: the exact "v1 rework" the design promised to avoid. Security lens loses its promised extension point; testability lens loses an injectable authn boundary.
- **Conflict note:** Karpathy would resist a speculative no-op seam — but the architecture *explicitly* decided (C4/D5) to lay it down so exposure could be gated later. The impl took the simplicity path against an explicit decision, so this is a deviation, not a defensible tie-break. Mitigation `127.0.0.1`-default + the DEPLOY tunnel caveat is real but is the *deployment* half of C4; the *code* half (the seam) is still absent.

## V2 — ARCH-002: the "global agent counter (≤1000)" and host-derived concurrency gate are enforced PER-RUN, not globally
- **Severity:** MEDIUM
- **Violated:** ARCH-002 ("concurrency gate `min(16,cores−2)`, **global agent counter (≤1000)** … these three caps together form the shared **RunGuard**"); scalability lens (single-node host-resource protection).
- **Evidence:** `src/run-guard.ts:5` `const AGENT_CAP = 1000;` gates `nextAgentId()` against the **per-instance** `_agentsIssued` (`:17,46-52`); likewise `concurrency`/`_inFlight` are per-instance (`:13,18,26-44`). `RunManager` builds a **fresh `RunGuard` per run** — `run-manager.ts:127` (`start`) and again in `_requireLive` rehydrate — each seeded with `this._concurrency = Math.max(1, Math.min(16, cpus().length-2))` (`:92`). There is no cross-run/global guard anywhere.
- **Failure scenario:** the `cores−2` number is a **host-CPU-derived** cap and the agent counter is explicitly labelled *global*, yet both are per-run. The v2 scheduler firing loop (`server.ts:453-469`) and any client submitting K runs make total in-flight agents = K × min(16,cores−2) and total agents = K × 1000 — both host caps multiplied without bound, over-subscribing the 16 cores and defeating the ≤1000 ceiling as a global resource limit. Resource-exhaustion / DoS surface on the single node, made more reachable now that the scheduler can launch runs autonomously.
- **Conflict note:** C2 ("a run is single-authority/single-host … scale is across runs") licenses *budget* being per-run (correct — budget is a per-run REQ-002 quantity). It does **not** license making the explicitly-*global* agent counter or the host-CPU-derived concurrency gate per-run. Minimal fix consistent with C2: a process-global agent counter + a process-global concurrency semaphore shared across every run's `RunGuard`, leaving budget per-run.

## V3 — ARCH-007 INV + ARCH-005 key-custody: workspace confinement is enforced only for the two default file tools' literal path args; Bash opt-in, symlinks, and other file tools bypass it (residual, downgraded from HIGH)
- **Severity:** MEDIUM
- **Violated:** ARCH-007 INV ("agent file I/O **confined to the run workspace**, run A cannot see run B, workflow X's folder unreachable from Y … **refuses to resolve outside it**"); ARCH-005 ("**sole custody of provider API keys** (parent-only)"); load-bearing rationale D6/C1.
- **What IMPL-064 fixed (acknowledged):** the *default* surface is now genuinely confined — no `Bash` by default (`claude-agent-sdk-client.ts:118`), `permissionMode:'default'` (`:261`), and a `canUseTool` path-deny (`:140-148`). A default `agent()` call can no longer `Read` the LiteLLM proxy's on-disk `config.yaml` (the real provider keys) or a sibling run's workspace. That closes the common path and is why this is no longer HIGH.
- **Residual evidence (the confinement INV is still not a general property):**
  1. **Bash opt-in bypass.** `Bash` remains fully supported as an agentType opt-in via `req.opts.allowedTools` (`:233-236`; comment `:115-118` says so explicitly). `makeCanUseTool` (`:140-148`) only inspects `options.blockedPath ?? input.file_path`; a `Bash` tool call's input is `{command}` with **no** `file_path`, so `candidate` is `undefined` and the callback returns `{behavior:'allow'}` (`:143-146`). An agentType with `Bash` can `cat <workRoot>/.../config.yaml` or `../otherRun/journal.jsonl` and return it to the untrusted script — the exact HIGH scenario, merely gated behind one agent-definition line rather than being the default.
  2. **Symlink bypass.** `isInsideWorkspace` (`:124-128`) uses `path.resolve` (lexical), not `fs.realpathSync` — a symlink *inside* the workspace pointing outside resolves to an in-workspace path and passes, so `Read` follows it out. The INV's "refuses to resolve outside it" is not met for symlinked paths.
  3. **Other file tools uncovered.** Only `file_path` (Read/Write) is inspected; `Edit`/`Glob`/`Grep`/`NotebookEdit` use `path`/`pattern`/`notebook_path`, so any of those opted-in escapes the check.
- **Failure scenario:** an agent definition (`agents/*.md`, loaded by `loadAgentDefinitions`) grants `tools: Bash` to some agentType; a workflow script calls `agent("...", {agentType:'shell'})` and prompts it to read an absolute host path → provider keys / cross-run data exfiltrated through the boundary ARCH-005/ARCH-007 say contains them.
- **Conflict note (three-way):** headless execution needs non-interactive approval and a tool-capable agent *is* the product (security ⟂ capability). The default-surface fix respects that. But ARCH-007's INV is stated as a *general* confinement property; a `file_path`-only, lexical, Read/Write-only check does not deliver it. Minimal architecture-consistent fix: root the CLI subprocess's filesystem (OS-level, e.g. a per-run rooted mount/uid) *or* keep provider keys off any filesystem an agent can reach *or* make `canUseTool` realpath-based and argument-name-complete (and treat `Bash` as always-deny-outside-root by parsing its command, or keep it un-grantable). Karpathy does not rescue a `file_path`-only check against a stated general INV — that is under-building against the invariant.

## V4 — ARCH-002 ⟂ ARCH-003: the per-call budget reservation now reserves HALF the total budget, still capping `parallel()` at 2 concurrent calls under a tight budget (downgraded from MEDIUM)
- **Severity:** LOW
- **Violated:** ARCH-003 (`parallel()` is meant to run its thunks concurrently); ARCH-002 intent that budget accounting and concurrency coexist.
- **What IMPL-064 fixed (acknowledged):** the prior fix reserved 100%-remaining, collapsing `parallel()` to exactly 1 always. D-V2G8-2 changed `reserve()` to `Math.min(remaining, this.total / 2)` (`run-guard.ts:92-98`), so ≥2 calls can proceed and the generous-budget common case (IT-037) regains concurrency.
- **Residual evidence:** `run-guard.ts:95` reserves a flat `total/2` per in-flight call; `assertBudget()` throws once `_spent + _reserved >= total` (`:68-72`). So at most **2** concurrent reservations fit before the 3rd throws. `run-manager.ts:338` takes the reservation before `acquireSlot()` and `_handleAgentRequest`'s `makeParallel` swallows the throw to `null` (`guards.ts:78-85`). For `budget=1000; parallel([a,b,c,d])`, calls `c`,`d` throw `BudgetExceededError` → `[<a>,<b>,null,null]` — silent partial concurrency loss on any budget where a single call could plausibly cost >½, independent of core count or how many thunks the user batched.
- **Stale-doc note:** `run-manager.ts:332-337`'s comment still says reserve "this run's **entire** currently-remaining budget" — it now reserves half; the comment contradicts the code it documents (self-sustainability / testability readability drift).
- **Conflict note:** this is the consistency (V2/prior fix) ⟂ scalability (concurrency) trade made with a blunt constant. A per-call *estimate*-based reservation reconciled against real spend in `capture()` (the fix the original V2 conflict-note recommended) preserves the hard ceiling without an arbitrary 2-call cap. LOW because it only degrades under genuinely tight budgets and never overshoots the ceiling; flagged because `total/2` is a magic constant standing in for the missing per-call estimate, not an architecture-derived value.

## V5 — ARCH-003: determinism guards are bypassable; the process boundary does not back them (carried, LOW)
- **Severity:** LOW
- **Violated:** ARCH-003 ("determinism guards (`Date.now`,`Math.random`, argless `new Date()` throw)"); indirectly REQ-006 replay integrity (the resume cache assumes deterministic re-execution).
- **Evidence:** `src/sandbox/guards.ts:163-175` builds the VM context with host-realm functions (`agent`, `parallel`, `pipeline`, `workflow`, `phase`, …). `node:vm` is not a realm/security boundary, so a script reaches the host realm's `Function` via e.g. `parallel.constructor.constructor('return Date.now()')()` and calls the **real** `Date.now`/`Math.random`, defeating the guarded `Date`/`Math` injected at `:172-173`.
- **Conflict note (unchanged):** for secrets/network/fs the architecture is right that the *process* boundary, not the VM, is the real defense (an escapee lands in a child that — modulo V3's residual agent-CLI reach — holds no keys/store/network). But **determinism is not a process-boundary property** — the child has a real clock/RNG — so this guard is only advisory and the resume-cache correctness that leans on it is weaker than ARCH-003 states. LOW because the threat model is Claude-generated (non-adversarial) scripts; flagged so the design text stops implying determinism is *enforced* rather than *encouraged*.

## What the impl got right (adversarial lens, for balance)
- **Prior HIGH materially reduced:** the default `agent()` tool surface is now curated (`Bash` off, `Read/Write` only), `permissionMode:'default'` restores tool-call arbitration, and a `canUseTool` boundary + `settingSources:[]`/`strictMcpConfig:true` (`claude-agent-sdk-client.ts:261-285`) deterministically strip host MCP/plugin leakage. Real progress, not a paper fix — V3 survives only as the residual opt-in/symlink/tool-coverage gaps.
- **Env custody (D-G8-5):** `buildSubprocessEnv` allowlist (`claude-agent-sdk-client.ts:167-181`) plus the never-real `DUMMY_API_KEY` (`:160`) genuinely keep host secrets out of the spawned CLI's env.
- **Atomic budget gate (D-G8-6):** `reserve()`/`releaseReserved()` taken synchronously between `assertBudget()` and any `await` (`run-manager.ts:331-338,378`) closes the prior TOCTOU overshoot — V4 is only the residual concurrency-cap tuning, not a regression to the race.
- **Nested-`callSeq` namespacing (D-G8-1):** `RunManager._nestedCallSeq` (`run-manager.ts:311`) keeps a nested `workflow()`'s journal from colliding with the parent's, protecting resume-cache replay integrity.
- **Testability seams (C3):** gateway/store/spawner/clock constructor-injected (`run-manager.ts:87-96,128`); `queryImpl`/`fetchImpl`/`mcpProbe`/`proxyManager`/`ticker` injectable (`claude-agent-sdk-client.ts:29`, `server.ts:448,453`) — the promised master test seams exist and are wired to real defaults at the composition root.
- **Bind default (ARCH-001/D5):** `bind = config?.bind ?? '127.0.0.1'` (`server.ts:409`) — compliant, `0.0.0.0` opt-in.
- **Fail-fast validator (ARCH-008/D-VAL):** thin submission facade sharing the catalog/alias table (`server.ts:433`), ownership not inverted.
