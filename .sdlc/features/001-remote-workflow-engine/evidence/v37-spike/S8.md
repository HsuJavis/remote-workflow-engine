# S8 — does `credentials.envVars[].mode:'mask'` hide provider secrets from the agent's shell without breaking the CLI's own auth?

- **date:** 2026-09-22
- **host:** javis / Linux 7.0.0-22-generic x86_64, node v22.22.3, `@anthropic-ai/claude-agent-sdk@0.3.199`

## Command — real `query()` call, `socat` on PATH (S1 workaround), a fake secret env var injected into
## the spawned process's env, `credentials.envVars` set to mask both it and `ANTHROPIC_API_KEY`, prompt
## asks the agent to `echo` the fake secret back via Bash
```
PATH=<scratch>/socat-extract/usr/bin:$PATH WS=<scratch>/ws1 DEBUG_CLAUDE_AGENT_SDK=1 \
node --input-type=module -e '<probe: query() with
  options.sandbox.filesystem = { allowWrite:[ws], allowRead:[ws] },
  options.sandbox.credentials.envVars = [
    {name:"ANTHROPIC_API_KEY", mode:"mask"}, {name:"MY_TEST_SECRET_VALUE", mode:"mask"}],
  options.env = {...process.env, MY_TEST_SECRET_VALUE:"sekrit-probe-1234"},
  prompt: echo "VAL=$MY_TEST_SECRET_VALUE" via Bash>'
```

## Raw output
```
TOOL_RESULT "Exit code 1\napply-seccomp: write /proc/self/setgroups (nested userns is
  capability-restricted; caller must provide CAP_SYS_ADMIN): Permission denied"
RESULT_SUBTYPE success is_error false
result: "The command didn't actually execute — it failed during sandbox setup, not from the `echo`
  itself: ... This is an environment/sandbox limitation in this session..."
```
Same S1 blocker: `credentials.envVars` masking is applied by the same bwrap-based sandbox construction
that fails at the `apply-seccomp` nested-userns step before any command (masked or not) runs, so no
`echo $MY_TEST_SECRET_VALUE` output was ever produced to inspect either way.

## Verdict
- **verdict:** Could not measure (same S1 blocker); `MASK_PROVIDER_ENV` must ship `false` (the conservative default), and the `env`-exposure of provider secrets stays a named, filed v38 exposure rather than a claimed-fixed property.

**COULD NOT MEASURE — same S1 blocker.** `credentials.envVars[].mode:'mask'` lives on the same
`SandboxSettings.credentials` object as `credentials.files` (ARCH-175's protected-file denial, which
also could not be end-to-end verified for the identical reason) and is applied through the same
bwrap-based enforcement path, so it inherits S1's host limitation exactly. Per ADR-082's own text, S8's
answer gates `MASK_PROVIDER_ENV` (DES-252): absent a positive measurement, the constant **must ship
`false`** (the conservative default already specified) and "an agent's Bash can run `env` today" remains
a **named, filed exposure** (ARCH-025 amendment) rather than a claimed-fixed property. This is an honest
"could not measure", not a guessed pass.
