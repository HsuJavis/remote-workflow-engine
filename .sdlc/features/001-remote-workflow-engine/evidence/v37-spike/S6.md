## Static confirmation of the resolution rule (read from the installed `sdk.mjs`, not the docs)
`node_modules/@anthropic-ai/claude-agent-sdk/sdk.mjs`: unless `options.pathToClaudeCodeExecutable` is set, the SDK resolves the executable via `require.resolve` against a fixed list of optional platform packages (`@anthropic-ai/claude-agent-sdk-linux-{x64,x64-musl}` etc, function `lI()`/`Sgp()`-style resolution) — it never consults `PATH`. The PATH-installed `claude` is reached only if the caller explicitly sets `pathToClaudeCodeExecutable`.

- **verdict:** bwrap+unshare present and permissive (userns enabled), socat absent by default; `query()` spawns the bundled `@anthropic-ai/claude-agent-sdk-linux-x64` binary (2.1.199), not the newer PATH `claude` (2.1.278), confirmed empirically via debug-log spawn line.

**bwrap 0.11.1 and unshare are present; `unprivileged_userns_clone=1`, `max_user_namespaces=123851` (both permissive); `socat` is NOT installed by default (blocks the CLI's own sandbox dependency preflight — see S1/S9) and requires either root (`apt install socat`) or a user-space extraction (demonstrated in S1, no root needed) to obtain.** Addendum: by default `query()` spawns the binary **bundled inside `@anthropic-ai/claude-agent-sdk-linux-x64` (v2.1.199)**, confirmed both statically (resolution code) and empirically (live debug-log spawn line) — **not** the newer PATH-installed `claude` (v2.1.278). This matters directly: any `Options.sandbox`/`SandboxSettings` field that exists only in 2.1.278+ would silently be absent/ignored against the binary actually spawned unless `pathToClaudeCodeExecutable` is set or the SDK's own bundled-binary optionalDependency is upgraded in lockstep with the SDK version pin (DES-253's exact-pin rider).
