# Efficient large-codebase seeding — design record

> Status: **DESIGN / accepted** (2026-08-01). Synthesized from a 4-architect panel debate
> (first-principles · distributed-systems · adversarial-security · consumability), two rounds with
> cross-examination. This records the accepted architecture + the roadmap so it isn't re-litigated.

## Problem

Seeding a run's workspace (and the sibling `asset_push`) is `files:[{path, contentB64}]` — full
base64 content in the MCP JSON body. Confirmed pain:
- base64 = **+33%** wire size; the whole blob is buffered in memory.
- Hard **8 MiB body cap** (`MAX_BODY_BYTES`) → a large codebase can't be pushed in one call (raw 413).
- **Zero dedup** → re-aligning a mostly-unchanged codebase re-transfers everything.

## The accepted architecture (panel-unanimous)

**Substrate = a content-addressed blob store (CAS, keyed by sha256) + a manifest/plan handshake.**
This is NOT reinventing git — it mirrors the engine's OWN shipped code: `workspace-artifacts.ts`
`listArtifacts()` already emits the `{path, size, sha256}` manifest, `readArtifactChunk()` is the
chunked transport, and `materializeSeed()` is the assemble step. The IN direction is the mirror of the
shipped OUT direction.

```
client helper                              server (single Host/Origin-guarded HTTP surface)
─────────────                              ────────────────────────────────────────────────
walk (git-aware) → {path,sha256} manifest  ── plan ──▶  missing = blobs THIS subject must upload (NOT global)
upload only `missing` blobs (zstd stream)  ── PUT ───▶  hash received bytes, store under COMPUTED hash, immutable CAS
                                           ── assemble ▶ per-path materializeSeed guardrails → reflink into workspace
```

### Three refinements the debate extracted (these make the CAS actually pay off)
1. **Manifest source = git-tracked ∪ dirty − `.gitignore`, not a blind full-tree walk.** The client
   never hashes `node_modules`/build output — the "hash 100k files" cost vanishes at the source.
2. **The blob store MUST be persistent + cross-push + per-project.** If `missing` is computed only
   within one push, you re-transfer the unchanged 99%. The delta win over "just gzip + raise the cap"
   lives entirely here.
3. **git plumbing is the CLIENT-side stat-cache, NOT the transport.** Memoize `gitOID → sha256` in a
   sidecar; only hash blobs whose git OID is new → re-align is `git status`-fast. A non-git directory
   falls back to a hand-rolled walk. Both emit the identical `{path, sha256}` manifest → one server CAS.

### Security invariants (day-one, before OIDC — so multi-tenant is an enforcement flip, not a rewrite)
1. **`missing` is per-subject** ("blobs YOU must upload"), never global existence → closes the
   cross-tenant dedup oracle (Harnik/Dropbox-2011 confirmation attack).
2. **The server byte-verifies every upload**, stores under the **computed** hash (never the claimed
   one), with **no exists-skip fast path** → closes hash-poisoning AND confused-deputy exfil at once.
3. **Guardrails run at ASSEMBLE, per manifest `path`** (`materializeSeed` already is this): `.claude`
   strip → `.git` reject → `isPathContained` realpath → write → apply exec bit.
4. **Admission = the `missing` ticket** (only asked-for hashes accepted) + per-tenant quotas (logical
   bytes + entry count) + immutable-pool refcount GC (pin blobs during assemble).

### Manifest entry schema (fidelity vs safety — resolved)
```ts
{ path: string, sha256: string, exec?: boolean }   // REGULAR FILES ONLY
```
- **`exec?:boolean`** (masked `& 0o755`; setuid/setgid/sticky unrepresentable) → runnable scripts keep
  `+x`. Categorically safe: grants no capability the jailed agent lacks, nothing auto-executes, and the
  `.claude`-strip (not the exec bit) is the RCE gate.
- **No `mode:int`, no `symlink`/`type`/`target` — ever.** Symlinks are unrepresentable and rejected.
  Rationale is retrofit-avoidance: adding `symlinkSync` to the privileged pre-agent assemble turns
  every future "tree-walker forgot `isPathContained`" bug from harmless into host-file exfiltration.
  `node_modules/.bin` is install output (regenerated by `npm/pnpm install`), submodules are gitlinks
  (materialized by `git submodule update`) — a seed is a *starting tree the agent builds from*, not a
  frozen runnable image, so "no symlinks" seeds a WORKING tree, not a crippled one.

### Transport
- **Blobs** go over a raw-streaming `POST /assets/blob/<sha256>` behind the **same** Host/Origin
  allowlist (+ future OIDC) — no base64 (+33% gone), stream-to-disk with on-the-fly hashing, no 8 MiB
  cap (its own per-blob size + per-tenant quota instead). A batched framed `POST /assets/blobs`
  recovers tar-like batching for the many-small-files profile, committing each frame as it completes
  (mid-batch disconnect → resumable).
- **Manifest-plan + assemble** stay MCP tools (small JSON the agent orchestrates).
- **Compression: per-blob, streaming, zstd (gzip fallback); dedup-then-compress** (address = sha256 of
  RAW bytes; store zstd-at-rest). Never whole-batch tar.gz (can't range-resume, re-compresses blobs the
  server already has).
- Resumability is FREE: the CAS is the checkpoint. Interrupted at blob 900/1000 → re-run plan →
  `missing` returns only the 100 not-yet-stored. No separate resume protocol.

### Rejected options (with the decisive reason)
- **rsync** — a second network surface that bypasses `materializeSeed` (guardrails don't run) + a
  second auth root disjoint from OIDC. Unanimously rejected.
- **git-bundle as transport** — the baseline commit (`workspace-git.ts`) is engine-minted AFTER seeding
  as an unrelated DAG with no common ancestor, so `bundle serverRef..HEAD` is empty → zero delta;
  recovering delta needs a per-tenant bare repo (the CAS's alleged sin, ×tenants) whose fetch
  negotiation IS an existence oracle that also serves any reachable object. Strictly worse here.
- **rsync rolling-hash (block delta)** — many-small-files makes it slower; lockfile re-send is killed
  by zstd; **content-defined chunking (FastCDC) in the same CAS** is the escape hatch if telemetry ever
  shows large-file re-transfer dominating.
- **engine-pull `seedRef:{repoUrl,sha}`** — egress/SSRF surface; kept as an OPTIONAL, egress-allowlisted
  transport for the CI/forge/air-gapped case (client isn't the code-holder), layered on the SAME
  CAS-assemble — never the default.

## Roadmap (vertical slices)

- **Slice 1 — immediate win (unanimous "do first"):** accept `Content-Encoding: gzip/deflate` on the
  seed/asset request body (bounded decompressed size — no gzip bomb) + turn the raw 413 into a typed,
  actionable error (`SEED_TOO_LARGE {bytes, cap, hint}`). 3–5× headroom for code, a usable error,
  zero design risk, on the path.
- **Slice 2 — the CAS substrate:** the content-addressed blob store (persistent, per-project,
  namespace-scoped) + `seed_plan`/`blob_put`/`seed_commit` primitives + the raw-streaming blob route +
  assemble-from-CAS through `materializeSeed`, with the four security invariants + the `{path,sha256,exec?}`
  schema. This is the main event.
- **Slice 3 — client helper (plugin repo):** `push_workspace.py` (git-as-client-cache + non-git
  fallback) mirroring `pull_workspace.py`; a `rwe seed <dir> --run <id>` CLI; an LLM-facing `seedFrom`
  that hides the whole dance. Small-tree (≤ ~4 MiB) inline fast-path (no handshake).
- **Slice 4 (optional) — `seedRef` engine-pull** behind an egress allowlist, for CI/forge/air-gapped.

## Backward compatibility
Today's `seed:[{path,contentB64}]` and `asset_push` keep working untouched — every new path is additive.
The helper auto-picks: small tree → inline as today; large → the CAS path. A 3-file skill never handshakes.
